# Windows folder/similarity integration

The coordinator dispatches Windows READ_FOLDER/GET_SIMILAR to the reviewed
ordinary-drive engine and retains the separate FILE_INFO stat capability.
The existing two filesystem owners, host leases, request validation and
cancellation remain responsible. Native enumeration uses checked bounded NT
records and verifies the actual held DOS and GUID volume; it creates no media
grant, path fallback, thread or child.

The shared Windows path module is declared only for Windows. Target features add
Wdk directory-query and IO bindings to the existing windows-sys package. Both
workspace and desktop manifests resolve with their unchanged locked dependency
graphs. Linux/Darwin continue through the existing POSIX implementation.

The historical stat-worker fixture now deliberately constructs an ordinary
local spelling for successful folder/similarity dispatch and separately requires
typed rejection of canonical verbatim listing inputs. FILE_INFO retains its
wider accepted verbatim scope. The shared Windows source suite compares actual
empty folder/similarity results rather than expecting the former blanket
unsupported-platform result.

Private integrated checks pass strict all-target Clippy for Linux, Windows GNU
and macOS ARM, all nine Linux Rust tests and nineteen focused pinned-Node source
suites with no skips. Two portable helper controls execute the actual immutable
source's empty folder/similarity functions; they assert no Windows filesystem
observation. All source gates normalize checkout/Git CRLF and still enforce
fixed source hashes and reject actual edits.

Main integration also passes493 Rust,584 source/harness and20 frontend checks,
352 Linux native executions across36 targets, strict workspace/native lint and
the normal production builds. The actual187-step Linux editor, four menus and
both drop scales pass; independent validation preserves typed metadata, JPEG
pixels,141 HTTP responses, unchanged blocker/sentinel and actual process exit.
These are Linux checks, not new Windows listing runtime evidence.
[Current local receipt](../baselines/windows-listing-audio-linux-local.json).

Actual Windows listing execution remains pending. The thirteen new engine test
bodies compile, alongside the eleven existing stat cases and the three pure
lexical module cases. Their real Windows/source corpus must pass native CI
before folder/similarity runtime evidence is claimed. Existing stat's DOS-prefix
mounted-volume caveat remains separate; the new scanner uses the stronger actual
GUID volume check. Foreign GUI behavior, unrestricted paths/volumes, mutation
snapshots, physical media and performance remain unproven.
