# Native Spotify playback command host

This slice composes the sealed Linux transport foundation with `NativeSpotify`. It adds no `main.rs` route, frontend bridge, private numeric wire parser, account integration or GUI evidence. Base: `4027466e`; original source: `2d94defcf98175e4f5c9504e7f4fd1d33c35c975`. Existing state-query behavior remains covered by its seven actual private-bus/source scenarios.

## Native API and source response

`NativeSpotify::dispatch(&LibraryService, Request, window)` now accepts exact `MAIN.SPOTIFY_COMMAND` as well as the existing state command. It returns one original `MAIN {channel:"SPOTIFY_COMMAND",data:true}` event with the original optional listener and the real current request context. This means accepted scheduling, not child exit, Spotify application, playback or server acknowledgement. There is no second completion event or `nativeSpotify` hydration metadata on playback replies.

The event's serde-skipped `NativeLifetime` owns the actual `CommandReceipt`. Event clones and real native encoding retain the same whole-job permit; JSON cannot reconstruct that authority. The fixed transport owner independently retains accepted work until its actual child/continuation settles even after caller abortion, receipt/event disposal or a failed publication. The host does not spawn a completion observer for each command.

`status()` is an optional native-only readonly observation of actual foundation capability, late command diagnostics and joined/drained state. Its context is the private process-owner identity, not the current request context. No public status event, completion ACK or console forwarding is added; coordinator owns any later native diagnostic routing.

The host validates the main role, exact full library/runtime context, listener UTF-8 length at most 8192 bytes and bounded command payload before lazy transport startup. Payload traversal is bounded to depth 16, 4096 nodes and 64 KiB charged bytes (32 bytes per value plus actual string/key UTF-8 bytes). It validates without first serializing or cloning ignored values. The supported command names are exact `playpause`, `next`, `prev`, `pause`, `setVolume`, and `seek`. The first four ignore bounded value shapes, including null, booleans, arrays and objects. The numeric commands require a present finite native Number. Missing values, null/string/bool/object coercions, unknown commands, unsafe track IDs and unsupported numeric ranges remain explicit native errors; the source's broader no-op/coercion behavior is not claimed.

`dispatch_with_number(&LibraryService, Request, window, number: f64)` is an additive native-only seam for a separately validated exact numeric decoder. It requires an actual numeric `payload.value` and an exact `seek`/`setVolume` command; wrong command/kind, missing input and nonfinite override reject before admission. It uses the supplied binary64 value directly. Ordinary `dispatch` uses only the existing `Value::as_f64()` result. The generic current Request parser lacks `float_roundtrip`, so ordinary JSON parsing is not proof of every source IEEE bit pattern. Coordinator-owned same-frame raw numeric decoding and send-time frontend selector snapshots are still required for that integration claim. This slice changes no global serde features.

## Ownership and retirement

The existing State mutex serializes lazy owner creation, admission, close and registry changes. A separate vector retains at most four strong, lease-free `(full request RuntimeContext, CommandControl)` pairs. Admission, context notification, sealing and completed shutdown prune only `control.settled()`. No elapsed time, dropped event or completion counter is used as that settlement proof. Ordinary idle has no cleanup timer.

`context_changed(real_current_context)` explicitly cancels obsolete command controls; `seal` cancels every remaining command control and seals the existing transport. A command publication that fails the actual final LibraryService context fence explicitly cancels its accepted intent too. The native process owner identity, captured executable/session and existing state service persist across an ordinary library switch; they are not published in place of the real request context. Caller/event Drop intentionally does not cancel command intent. State queries retain their existing cancellation-on-caller-Drop semantics.

`shutdown` keeps the same service through the existing two-second observer timeout and retry. The foundation's bounded lifecycle observers, anchored actual children, sticky failures and actual OS-thread join remain authoritative. Settled controls are pruned even when shutdown returns a terminal error; pending controls remain retained on timeout. Ready events can still hold quota after real join, including across a replacement host; this is deliberate and bounded by the same global four whole-job permits shared with state queries. The host adds no task, thread, runtime, network listener or executable lookup algorithm.

Coordinator obligations: route only the supported MAIN command, supply the actual selected context, preserve the event guard through actual native encoding/disposal, snapshot and validate the original numeric primitive kind before generic JSON transport, call context retirement explicitly and await actual Spotify shutdown before disposing its host/dependencies. A parsed numeric Value alone cannot prove that a boxed/coercing JavaScript object was originally a Number. Emergency last-owner Drop still synchronously joins the foundation and may block an async executor; normal lifecycle must use explicit retained shutdown/retry. Accepted D-Bus effects cannot be undone.

## Evidence

The new focused native suite includes pre-admission role/context/listener/payload/numeric bounds plus eight controlled real Linux private-bus cases: held seek with later pause/volume; caller abortion after actual admission; stale selection and new-context reuse; actual final-context rejection without a notification; CLOSE with a real held child and retained cloned event; four ready events through encoding, join and replacement; four actual held seek controls rejecting excess command/state admission and all canceling on a real library switch; and exact native numeric edge values plus all four ignored-value commands. An independent GIO peer records actual effects. The complete immutable `executeSpotifyCommand`, its handler and `receiveMain` are executed separately for continuation order and numeric comparisons, including exact source reply/listener and void receive return. The native numeric seam deliberately receives different placeholder numbers in its ordinary Request; the source oracle consumes the actual IEEE bits. Direct-child exit is never substituted for the peer's observed effect.

The stale/final-context cases release the actual held peer after cancellation and assert `spotify_cancelled`, so a later timeout cannot masquerade as explicit cancellation. Actual native child PIDs, reaped counts, settled registry and real joined/drained status are checked. Early-event clones remain charged after the worker joins; deserialized JSON has no lifetime guard. Fixtures own and wait their native child, Node supervisor, private daemon, GIO peer and original source shell children on success/failure. No production desktop bus is used.

Focused verification uses only `/mnt/data/cache/freeshow-rust-build/spotify-command-host/{check,target}` with Rust 1.99.1, one Cargo job, debug information and incremental compilation disabled, offline cached dependencies and standalone headless manifest. The manifest imports the actual production files and existing core/Spotify dependencies; it does not build Tauri or alter shared manifests/locks. Node 22.21.1 and installed Python GI/dbus-daemon/dbus-send are required on Linux. Other platforms run honest pre-admission checks; foreign compilation does not certify a Spotify transport there. Main routing, raw/renderer transport, packaged GUI, real Spotify accounts and physical playback remain pending coordinator evidence.

Final checks: five top-level native tests passed, including all seven existing state/source child scenarios and eight new command scenarios. The new command scenarios observed 35 actual private-peer effects; the separate continuation/numeric source comparisons matched 21 of those effects against actual original source execution. Native fixtures joined their actual owner and waited all direct children; quota replacement additionally joins its separate replacement owner. Strict all-target Clippy, rustfmt, configured Markdown formatting and `git diff --check` passed; Windows GNU and macOS ARM checks are compile/lint evidence only.

Two deliberate local negative controls were restored afterward. Ignoring the exact binary64 argument caused an actual private-peer/source mismatch (zeros versus subnormal/exponent/next-bit values and rounded seek positions); removing context cancellation caused the released seek to finish without the required `spotify_cancelled` observation. Logs remain `/tmp/freeshow-spotify-command-host-{number,cancel}-negative.log`. A draft supervisor originally expected a standalone stdout release marker, whereas the Rust test harness prefixed its progress on that line; its rejected log is separate, and the corrected observer matches the actual line ending. Successful final logs use the restored implementation.
