# Linux release comparison harness

`scripts/migration/compare-releases.mjs` measures the observed application process tree for a visible, empty-library editor. It uses existing release binaries and never builds assets, installs packages, flushes system caches, or computes speedup ratios. This is measurement tooling, not evidence of completed application parity. The Rust release at declared source `c9e62492` is a **partial feature migration**; the same visible editor does not imply the same background feature set.

The official baseline is the verified packaged FreeShow `v1.6.7-beta.2`, source `2d94defcf98175e4f5c9504e7f4fd1d33c35c975`. The existing official-release readiness receipt is required. The harness checks the downloaded `.deb` against its published digest, records the selected executable and `app.asar` hashes, and verifies the actual packaged version at runtime. These hashes identify the selected extracted files; this runner does not reconstruct the package extraction or attest a Rust build from source. Supply the immutable Rust build commit and expected binary hash explicitly. The observed checkout HEAD/status are recorded separately because integration work may have advanced beyond the selected binary.

## Reproduce

Run from a checkout with the existing Playwright installation, Python 3, Xvfb, dbus-daemon, fontconfig, tauri-driver, WebKitWebDriver and the runtime libraries already available. No root permissions or delegated cgroup are required. The example paths are this machine's existing artifacts:

```sh
WEBKIT_WEBDRIVER=/home/rob-admin/.local/share/freeshow-native/usr/bin/WebKitWebDriver \
/home/rob-admin/.local/share/freeshow-oracle-node/node-v22.21.1-linux-x64/bin/node \
  scripts/migration/compare-releases.mjs \
  --source-root /home/rob-admin/GitHub/freeshow-rust \
  --rust-source-commit c9e62492 \
  --expect-rust-sha256 b1924acd481ec61baf80105be0734c4f7805caf64213d82ae0c81eda73909fbf \
  --font-dir /home/rob-admin/.local/share/freeshow-test-fonts/usr/share/fonts/truetype/noto \
  --pairs 5 --warmups 1 --settle 20 --seconds 10 --interval 250 \
  --order alternating --seed 42 \
  --output /tmp/freeshow-release-comparison-NEW
```

The output directory must be new or empty. `--electron-bin`, `--rust-bin`, `--electron-package`, and `--baseline-receipt` support other artifact locations. `--dry-run` performs provenance/tool/font preflight and writes the planned order without launching GUI processes. `TAURI_DRIVER` and `WEBKIT_WEBDRIVER` select existing driver executables. The native driver's returned new-session capabilities are preserved. A missing driver fails preflight, before Xvfb starts.

Default timing is one warmup pair followed by five measured pairs, 20 seconds settling and 10 seconds sampling per run, every 250 ms. Settling exceeds the retained UI's roughly 15-second startup request timeouts. A seed controls the first alternating order; `--order random` draws a seeded order separately for each pair. Warmups retain full raw evidence but are excluded from summaries. More than one pair is necessary to inspect variability; a short smoke is only an instrumentation check. Reserve an otherwise idle host and avoid concurrent builds, GUI tests, benchmarks and release-file replacement. Load averages are recorded, but the harness cannot enforce an idle machine.

Every run receives a fresh private home, app store, data library, XDG directories, cache, runtime directory and session bus. Both receive the same normalized configuration: English initialized editor, no shows/media/projects, outputs empty, automatic output/updates and configurable remote/stage/controller/stream/Companion servers disabled. Private paths are verified and removed after the run. The same extra fonts are copied into each private XDG data directory. The normalized seed hash, individual system/extra font hashes, and font-manifest hash are retained. Full body text is not compared because versions and clocks differ; matching navigation, empty-library labels, visible editor readiness and exact CSS viewport/DPR are checked before and after each interval and across runs.

One private Xvfb serves all runs at 1600×1100×24, 96 DPI; application content is resized to 1280×800 CSS pixels. Both use `LANG=LC_ALL=C.UTF-8`, `GSETTINGS_BACKEND=memory`, `GDK_BACKEND=x11`, `LIBGL_ALWAYS_SOFTWARE=1`, the seeded hardware-acceleration preference, and the same documented environment. Electron also receives `--no-sandbox --disable-gpu`; WebKit receives `WEBKIT_DISABLE_COMPOSITING_MODE=1`, `WEBKIT_DISABLE_DMABUF_RENDERER=1` and automation enabled. These are distinct engine switches, not proof of identical rendering paths. No physical-GPU or desktop-hardware claim follows from Xvfb. Selected inherited library/font overrides are recorded without dumping unrelated environment variables.

Application/XDG caches are fresh on every run. The OS page cache is **not** cold: provenance hashing reads binaries, the package, assets and fonts, and previous runs warm caches. There is no global cache eviction. Warmup pairs do not change this per-run application-cache policy.

## What is measured

Each raw `samples.jsonl` record includes the phase, monotonic collection start/end, host uptime, every observed process's PID plus start-time identity, parent/session/group IDs, command/executable/arguments, selection reasons, user+system CPU ticks, RSS/PSS, memory-read failures and any PID change/exit during collection. The `/proc` scan is limited to this UID and 20,000 process entries. It scans same-UID environment blocks only to test a private run marker; unrelated environment values are not saved. Selected process argv and application logs remain inside the private output directory.

The exec-only launcher creates a private session and writes its identity before replacing itself with the app. Membership combines that root identity, current ancestry, private session/group, previously observed identities, inherited run marker, and an optional dedicated cgroup. This includes Electron zygote/GPU/utility/renderer/crashpad processes and Tauri WebKit network/web processes. Retained identities and marker matching keep helpers after reparenting or `setsid`; PID reuse cannot inherit an old identity. The smoke observed a detached crashpad with a different session ID through its marker. Known helpers remain in membership evidence through exit. The observer, Playwright/WebDriver control processes, Xvfb, Python supervisor and private session bus are outside app accounting. Externally activated services are outside this boundary.

Membership is **observed**, not omniscient. A helper that clears its marker, escapes its session, and reparents before any sample can be missed without cgroup containment. Permission-denied marker metadata for unmatched same-UID processes and scan errors are reported. They cannot be assumed to belong to the app or silently treated as proven unrelated. An optional delegated cgroup improves containment; lack of delegation does not produce a false exact result.

| Field                             | Meaning and limits                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pssSumBytes`                     | Primary candidate: summed proportional resident shares for every observed living process, read from `smaps_rollup`. A run distribution is emitted only when **all** steady samples have complete PSS. It is not a unique physical-memory total.                                                                                                                                                                                                            |
| `coverage`                        | Exact total/complete/incomplete sample counts and identities/reasons missing PSS. An exit/PID change during reads invalidates that sample's PSS. Zombies contribute zero resident memory.                                                                                                                                                                                                                                                                  |
| `completeSampleSubsetPssSumBytes` | Distribution of fully readable samples only, explicitly a selected subset. It is not substituted for a full-run PSS distribution.                                                                                                                                                                                                                                                                                                                          |
| `perRunMedianPssBytes`            | Summary distribution of each run's median, emitted only when every measured run on both sides is valid and fully covered. Otherwise null on both sides. `completePssRunSubset` separately labels selected complete runs.                                                                                                                                                                                                                                   |
| `rssSumBytes`                     | Sum of per-process RSS; shared pages are counted repeatedly. Unreadable rollups use `/proc/PID/stat` resident-page estimates, marked per process. Never labeled unique physical memory or silently promoted to the primary PSS comparison.                                                                                                                                                                                                                 |
| observed CPU                      | Delta of each observed identity's own `utime+stime`, divided by `CLK_TCK`; no `cutime/cstime`, avoiding child double counting. CPU of helpers that exit between polls or are never observed can be lost, so the result is labeled a lower bound with sampling/clock-resolution limits. Late-discovered existing processes start at their first observation. Newly born processes start at zero only when their birth is unambiguously inside the interval. |
| CPU percent                       | CPU seconds / wall seconds × 100, where 100% means one logical core. `/proc` mode uses the observation envelope from the first collection's start through the last collection's end; individual process reads are not simultaneous.                                                                                                                                                                                                                        |
| `collectionMs`, observer          | Collection cost excluding JSON serialization/file writes; raw observer cumulative user/system CPU and RSS are included separately, never added to app totals. Polling competes with the apps.                                                                                                                                                                                                                                                              |

`distribution` uses nearest-rank p50/p95, with count/min/max. Summary distributions operate on per-run medians or per-run CPU percentages, not pooled samples masquerading as independent repeated trials. No confidence interval, significance test, ratio, physical-memory reduction or production-performance claim is generated.

An optional `--cgroup-parent /already/delegated/cgroup-v2` creates only a private child for each app. The launcher joins before exec; drivers/Xvfb/observer remain outside. `cpu.stat usage_usec` then captures subtree CPU, including exited descendants, with its own counter-read timestamps. If creation/delegation is unavailable, the error is preserved and `/proc` lower-bound CPU is used explicitly. The runner does not mount, delegate, chmod, enable controllers or change global cgroups. The optional cgroup path was **not exercised on this read-only-cgroup host**. Kernel definitions: [proc filesystem](https://docs.kernel.org/filesystems/proc.html), [cgroup v2 CPU accounting](https://docs.kernel.org/admin-guide/cgroup-v2.html).

No automation calls or screenshots occur during the steady interval. DOM checks, the read-only version/library observations and resizing precede settling; validation and screenshots follow sampling. Startup fields are diagnostic observations including different launch, debugger, driver, polling and resizing overhead. Electron's Playwright path and Tauri's WebKitWebDriver path have no comparable start boundary, so `startupComparable=false` and no startup speedup is reported.

## Artifacts and cleanup

`report.json` contains settings/order, environment, source/binary/tool/font provenance, all run records and descriptive summaries. Each run has `run.json`, `launch.json`, `launch-config.json`, `samples.jsonl`, application/driver/session-bus logs where available, and a post-interval `editor.png`. Logs and membership include launch/settle/validation/cleanup phases; only `phase=steady` contributes measurements. The executable hashes are checked again between runs. No application assets/binaries are modified.

The outer Python process is a Linux child subreaper. After observer exit it reaps adopted Chromium/WebKit helpers, kills remaining owned descendants after a bounded grace, and writes `supervisor.json` with reaped/killed PIDs, exit status, elapsed time and completion. It never kills by application name or a global PID search. Per-run cleanup first asks the adapter to close, then checks exact observed identities, sends TERM/KILL if needed, requires two quiet checks, stops support process groups and removes private profiles/cgroups. Zombies may appear in a per-run receipt before the outer supervisor reaps them; inspect the final supervisor receipt as well. Support start and adapter/network operations have explicit timeouts; cleanup has finite TERM/KILL bounds. An externally forced SIGKILL or machine crash can leave temporary profile files; the receipt retains their paths. Successful process-tree cleanup does not certify a previously unseen escaped helper.

## Validation receipt

Eight focused non-GUI tests cover proc parsing with unusual command names, RSS/PSS coverage and partial-subset suppression, CPU identity/birth accounting, PID reuse, deterministic paired/random order and bounds, visible workload matching, and a real exec/fork/setsid/reparenting/subreaper cleanup case. Python syntax compilation, CLI help, provenance-only preflight and formatting checks are separate checks. The final supervisor receipt and strengthened subset fields were added after the GUI smoke and validated with the focused tests/preflight and raw-sample reanalysis. New-session capability preservation was corrected after the smoke; that response path awaits the next real GUI run. None of these changes is represented as another GUI run.
