# Local scripture loading

This independent crate prepares the original `MAIN.BIBLE` reply for local `.fsb` files. The retained `scripture.ts::getLocalBible` / `loadJsonBible` flows remain unchanged. No host command, frontend, shared manifest, store, cache, directory or source file is modified by this slice. Online Bible APIs, XML/converter imports, search and slide generation remain retained frontend or separate work.

The immutable oracle is FreeShow `2d94defcf98175e4f5c9504e7f4fd1d33c35c975` (`1.6.7-beta.2`). The differential test obtains the actual `BIBLE` handler, `loadScripture`, `loadFile`, `parseJSON`, `readFile`, UTF-8 helper and directory helpers with `git show` and TypeScript declaration extraction. It runs those declarations in strict mode with real private files and controlled Electron roots. The reusable `tests/parity/lib/scriptures-oracle.mjs` exports `scriptureOracle(dataRoot, documentsRoot, options)` without test registrations; `.load(payload)` runs that exact handler, and `.loads`, `.reads`, `.errors`, `.alerts` and `.mkdir` expose boundary evidence. This same helper is available to the coordinator's desktop fixture. It does not copy a reference scripture algorithm or depend on mutable working-tree source.

## Integration contract

```rust,ignore
let service = ScriptureService::new(Limits::default())?; // exactly two OS workers
let context = ScriptureContext::new(selected_data_root, electron_documents_root)?;
let prepared = service.load(&context, &original_payload, library_cancel.child_token()).await?;
// Alternatively load_with_deadline(..., std::time::Instant) caps the whole wait.
```

`ScriptureContext` has private fields and no `Deserialize`. Both roots come from the trusted host; `documents_root` is the actual Documents root, not the selected library or an environment guess. `bibles_root()` and `legacy_root()` expose the derived roots. This context contains filesystem provenance only. The host retains its separately captured runtime/library context and validates it before directory effects and before publishing the completed reply. A context change must cancel pending work; the crate never advances a generation or publishes IPC.

`load` returns `PreparedScriptureReply { data: Option<Value>, diagnostics, folder_intents, stats }`. `is_complete()` is true only when data exists and no directory intent remains. Only publish `data` as the unchanged `Main.BIBLE` response, preserving the original request listener ID. Diagnostics/stats are native metadata, not additions to the Svelte payload. Missing files produce source `{error:"not_found",id}` data; unsupported/resource/cancel/deadline errors are explicit `Err`, never invented Bible content or a silent not-found success.

If the source-selected Bibles path is absent or its native `lstat` is not a direct directory (including an obstructing file or directory symlink), preparation returns `data=None` and `EnsureBiblesDirectory {path}` without reading either candidate or creating anything. Under its ordered, current-context owner, the host must attempt the original recursive mkdir. A mkdir failure still emits the original ALERT and must continue to loading/fallback. After that attempt, rerun with `context.after_directory_attempt()`; this native-only acknowledgement allows continuation even if mkdir failed. Revalidate before acknowledging/rerunning so an obsolete library cannot cause a directory write. Existing direct directories need no effect. This corrects the original Linux preparation, which skipped the source mkdir/ALERT when an existing file obstructed Bibles and skipped the original mkdir attempt for a directory symlink. The service does not repeat an acknowledged failed attempt or create the legacy Documents/Bibles directory.

Payload `name` must be a string. It receives the original literal `.fsb` suffix and Node-native `path.join` normalization (POSIX on Linux/macOS, win32 on Windows), preserving Unicode spelling, case, separators, embedded NUL handling and `..` behavior. No filename sanitization or NFC folding is introduced. The name is therefore not a sandbox boundary; host authorization/provenance remains its responsibility, as for the source handler. Missing/non-string names are explicitly unsupported. Missing ID uses `loadFile`'s default empty string; bounded JSON IDs, including null/falsy values, retain source behavior. Unused payload fields are ignored rather than cloned/walked.

## Exact source decisions

- The primary candidate is selected-data `Bibles/<name>.fsb`; the legacy candidate is actual Documents `Bibles/<name>.fsb`.
- The source calls `loadFile(primary,id)` once to choose the candidate, then **always calls loadFile again** on the chosen path. It does not return the first successful parse. If the first primary attempt errors, the second attempt uses legacy. If the first primary succeeds but the second primary disappears/fails, there is no new legacy fallback. The native implementation retains this behavior and does not cache the first bytes/parse.
- `loadFile` probes existence, then `readFile` independently probes and skips direct directories. Symlinks to regular files are followed; directory symlinks produce a read diagnostic, dangling/looping links normally fail existence without a read log. Missing/empty/falsy parsed content yields `{error:"not_found",id}`. Source read/parse error logs are represented as bounded diagnostics with the original log/no-log distinction and operation. `osCode` is the native raw OS error when available, not Node's negative libuv errno or string code. A Windows directory detected before open has no invented raw OS error number.
- UTF-8 follows `Buffer.toString("utf8")` maximal-subpart replacement; BOM remains literal U+FEFF. JSON first tries the full decoded text, then retries through its first `}}]` terminator, or its first two UTF-16 code units when no terminator exists. Unknown well-formed content is retained. Finite numeric tokens convert once to IEEE binary64, including 53-bit rounding, subnormals, a one-ULP decimal and negative zero. The parser preserves duplicate-key replacement position and JSON string escapes without enabling global serde parser features.
- A truthy ID replaces element/property zero in supported array/object content. Empty arrays gain element zero; falsy IDs retain the original stored element. A truthy primitive that cannot accept the source assignment is explicitly unsupported rather than returning a fabricated array.
- Legacy verse migration runs only when `content[1].books[0].chapters[0].verses[0].value` is truthy. Otherwise the remaining books/chapters/verses are not interpreted or repaired. When enabled, it visits the original arrays and, for each falsy `verse.text`, sets `text = verse.value || ""` and deletes `value`. Existing truthy text retains its old value field. Booleans, objects and arrays use JS truthiness; unknown fields and insertion order remain meaningful. Original values are moved, avoiding a second clone of unknown nested data.

`stats.load_paths` is bounded to two paths and exposes actual load decisions for tests. It is evidence of calls, not a claim of an atomic file snapshot: external edits can change either original read. The first result is deliberately discarded before the second, with conservative allocation accounting released at that stage boundary while retaining peak evidence and cumulative work counters.

## Bounds and lifecycle

Defaults (validated hard ceilings in parentheses): two fixed OS/file/parser workers; eight queued/admitted waiting jobs (32); 32,768 UTF-8 path bytes; 16 MiB aggregate actual reads across both attempts (32 MiB); 128 MiB conservative peak allocation account (256 MiB); 32 MiB serialized source reply (64 MiB); 500,000 cumulative parsed nodes (1,000,000); depth 32 (64); 4 MiB encoded JSON string tokens (8 MiB); 100,000 visited migration verses (200,000); 40 million counted operations (100 million); cooperative 10 s admission-through-reply deadline (120 s); and 3 s shutdown wait (30 s). IDs have an independent depth-eight, 128-node, 8 KiB scalar/key-byte bound. Reply metadata has at most two bounded paths, a fixed stats object and at most two source diagnostics.

JSON depth/node/operation and conservative allocation checks occur before growing containers or decoding strings. Read chunks are at most 32 KiB; file metadata and actual aggregate reads both enforce the byte bound. Reply serialization uses a counting writer, not an extra output-sized buffer. Allocation accounting conservatively includes buffers, decoded strings, container/entry overhead and migration growth. It is a deterministic allocation budget, not a measurement of allocator metadata, RSS or whole-process memory. Special unsupported values do not escape the JSON transport disguised as null.

Admission includes active, queued and completed-but-uncollected replies. A dropped or canceled caller cannot release a running job's permit: the worker owns it through actual synchronous completion, and its bounded response retains it until collected/dropped. No per-request thread, task, process, Tokio blocking-pool work or unbounded waiter queue is spawned. `status()` exposes live worker, active and admitted counts plus closing state. Future host-level effects/reply waiting need their own bounded lease.

Cancellation/deadlines are checked during read, decoding, traversal and output counting. Actual OS calls cannot be force-killed. Linux/macOS probes reject nonregular files; `O_NONBLOCK` and a second opened-file metadata check prevent a FIFO replacement from blocking in open. Windows rejects device/pipe namespaces and reserved-device components before lookup, follows ordinary file symlinks, and checks the opened handle with `GetFileType` plus regular-file metadata before reading. These conservative namespace/component rejections also exclude some source-readable extended-namespace files. Windows disk-file opens use `FILE_FLAG_BACKUP_SEMANTICS`, matching the flag in pinned Node 22.21.1 [libuv `fs__open`](https://github.com/nodejs/node/blob/v22.21.1/deps/uv/src/win/fs.c). This preserves existing process-privilege behavior without enabling privileges. Reads remain synchronous and have no Unix nonblocking guarantee. These checks do not make blocked network/filesystem syscalls interruptible or guarantee identity against external regular-file replacements. Shutdown closes admission immediately, cancels accepted work, closes the channel and waits for both fixed worker threads, including serialized shutdown ownership, within its deadline. A timeout returns `scripture_shutdown_timeout`; a later call can complete the join. Successful shutdown joins both threads. Dropping the last service cancels/closes without synchronously joining a possibly blocked worker; await shutdown before exit.

## Evidence and limits

The platform expansion enables Linux, macOS and Windows; other operating systems still return `scripture_unsupported`. The public service/context/reply API and all limits are unchanged. Native Windows paths support fully qualified drive, UNC and extended drive/UNC roots within the existing Unicode/absolute-root contract. The private lexical join preserves Node joining of later absolute-looking names rather than replacing the trusted parent. It does not case-fold, normalize Unicode, sanitize names or canonicalize filesystem identities. Local Windows join golden cases are spelling evidence only. Native UNC share access, arbitrary reparse providers and every Windows filename alias are not certified.

The Linux run passes 11 Rust tests and the Node corpus performs 221 real-file source/native comparisons, generating 32,544 verses including the full-sized 31,680-verse legacy Bible. Node reports 17 passing tests including four symlink subtests, with four genuinely OS-specific tests skipped on Linux (three Windows cases and the unsupported-other-OS assertion). It compares actual handler replies, property order, unknown fields, load paths and exact read/parse diagnostic operations. Source probes mutate/remove real primary files between reads; deterministic native worker barriers verify fresh second-read content, first-result fallback selection and no new fallback after second-read failure. No mutation observer is exposed in the production API.

The full-sized Linux fixture records 7,837,118 aggregate read bytes, 76,085,957 peak accounted allocation bytes, 325,134 parsed nodes and 9,456,890 counted operations under unchanged defaults. This is accounted allocation, not RSS. The corpus reports native platform, Node version, comparison count and capability skip reasons. Generic filesystem, parser, resource and lifecycle suites now run on all three native OSes. Permission bits are a POSIX-only probe; Windows separately uses a private-file ReadData deny ACL with bounded built-in PowerShell and restores it in `finally`. The test verifies the actual current-user explicit deny ACE, observes whether the pinned Node process can read despite that ACE, and compares the real source/native reply and diagnostic branch. A privileged runner may still read successfully. Only absence of that tool skips the ACL case. Symlink privilege failures skip each affected link case with the concrete error; Windows junctions are separately exercised. Alternate-stream creation is skipped only for an explicitly unsupported/denied native filesystem capability. Invalid Windows filename requests still compare real source/native missing-file decisions instead of being dropped.

Strict Clippy and Windows GNU/macOS arm64 all-target compilation pass locally. **The first native CI run passed macOS; Windows needs a fresh run after the corrections below.** No Linux simulation or cross compilation is presented as either OS's behavior evidence. The tests intentionally use native `path`, real native files and the actual pinned handler on each runner, rather than mocking another OS. Windows-only extended roots, alternate streams, junctions and device safety comparisons passed their first native core run. The ACL fixture failed because it assumed a read error although Node actually read successfully; it now compares the observed branch and retains explicit ACE verification. These cases remain unexecuted locally. Source checks of Node's [Windows existence boundary](https://github.com/nodejs/node/blob/v22.21.1/src/node_file.cc) and [libuv filesystem implementation](https://github.com/nodejs/node/blob/v22.21.1/deps/uv/src/win/fs.c) inform the native design; passing native CI is still required.

Rust tests cover independent byte/aggregate-double-read/node/depth/string/verse/allocation/output/operation bounds, bounded IDs, FIFO rejection, pre-admission cancellation/deadlines, fixed-worker concurrency, real admission overload, canceled queued work, dropped callers retaining work capacity, terminal rejection, shutdown timeout and retry. Node fixtures cover original malformed UTF-8/BOM/corrupt repair, Unicode/path spelling, scalar/default IDs, symlinks, directories, missing/permission failures and legacy precedence. The oracle uses standalone Node 22.21.1; this is not an actual packaged-Electron GUI run or a physical storage/performance comparison.

Explicit gaps: JSON lone UTF-16 surrogates, nonfinite-overflow numeric values, malformed migration containers/primitive writes and nonregular files return unsupported diagnostics. Unsafe source hangs/crashes and unbounded files/allocations are not reproduced. These limits intentionally reject some source-accepted inputs. Non-Unicode paths, broad parser fuzzing, external-edit atomicity, hard kernel cancellation, all concurrent shutdown/caller scheduling variants, online/provider formats, imports, renderer cache mutation, scripture search and slide generation are not certified. Windows device/pipe namespaces, volume/GLOBALROOT namespaces and reserved-device components return explicit `scripture_unsupported`; ordinary disk-file support does not certify network filesystems, all reparse providers or uninterruptible OS calls. Full Windows verification of the corrected reader remains pending native CI; macOS passed the first core/native run. No retained UI integration is claimed by this crate.
