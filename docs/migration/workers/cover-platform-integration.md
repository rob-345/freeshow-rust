# Native fixed-cover platform integration

The coordinator now dispatches the existing `CoverFiles` owner to the private
Darwin and Windows backends, alongside Linux. The same four whole-operation
leases, ordered library jobs, opaque descriptors, validation continuation,
independent alert receipts and retained HTTP finish remain in use. This adds no
worker, runtime, request-selected path or public file handle.

Windows HTTP projection accepts true native modified seconds only in
`0..=u32::MAX`, with canonical nanoseconds. Pinned Node 22.21.1 casts these fields
through a 32-bit unsigned long on Windows. Earlier/later raw native dates remain
accurate for version guards and become a retained `cover_mtime` failure before
headers; no guessed wrapping or missing-file success is emitted. The dedicated
native fixture first proves the requested 100ns-aligned time exists in both real
filesystem metadata and the native signed fields, then compares ordinary ETags
against actual pinned Node and its installed `etag` dependency.

The existing actual Source tests now cover ordinary files, missing files and a
real regular-file Audio blocker on all three supported systems. The actual TCP
host test serves the selected cover on all three bound ports and holds STOP
through an independent publication receipt before checking the per-run weak
owner. Mac test fixtures canonicalize their temporary roots because `/var` and
`/tmp` aliases are deliberately outside the backend's certified no-follow root
contract. Production paths are not canonicalized.

Local integration evidence is strict all-target compilation/lint of the actual
parent, backend, Source, publication and test composition on Windows GNU and
macOS ARM, plus 49 actual Linux test executions: eleven file, eight publication,
six Source and 24 remote-host cases. An initial private Linux harness run failed
two discovery tests because its worktree had no installed Node dependencies and
selected host Node 24. Reusing the existing dependency tree and pinned Node
22.21.1 passed both unchanged tests and the complete 49-case harness.

After merging the reviewed modules into the main branch, strict native all-target
Clippy, the production binary build and all 352 Linux native executions passed
across 36 test targets (two new OS-specific targets contain no Linux tests).
The rebuilt 187-step Linux editor, four menus and both drop scales passed again.
Independent receipt validation preserved all six ordinary now-playing cases,
three folder-failure sequences, both exact JPEG RGBA hashes, fourteen cover
phases/141 HTTP responses, unchanged blockers/old-library sentinel and actual
pending-write/backup Quit. The editor retains 55 expected diagnostics. The
portable JPEG/parser suite remains current because this integration changes
only native modules, platform dependency features, tests and documentation.

The first actual [platform CI run](https://github.com/rob-345/freeshow-rust/actions/runs/39247046026)
passes five jobs: all three core jobs, native macOS and Linux desktop. Native
macOS logs confirm all twelve dedicated filesystem cases, three Source cases,
and the actual three-port TCP/STOP lifetime test. Windows passed fourteen of
sixteen cases in its dedicated cover target; missing-Audio creation and a
parent-rename fixture assumption failed, and subsequent native targets were
not reached. The fixture now replaces the actual Audio namespace while retaining
its genuine earlier folder failure. Diagnostic assertions expose actual mkdir
NTSTATUS/Win32 evidence before selecting a production fix. No test is skipped
and no unobserved status is relabeled Missing. A corrected complete run remains
required. The diagnostic follow-up at `ef7fadfb`
([actual run](https://github.com/rob-345/freeshow-rust/actions/runs/39249175360))
again passes the other five jobs, and Windows passes fifteen of sixteen
dedicated cases. The corrected namespace-change fixture passes. Missing-Audio
creation reports actual NTSTATUS `0xC000000D` / Win32 87 (invalid parameter),
with the genuine retained folder failure; the later native targets remain
unreached. Production options were unchanged in that diagnostic run. A focused
create-option correction is now integrated with a creation-only object-parser
no-reparse guard. Two new native fixtures race an absent-target junction and an
ordinary file between the actual absent probe and FILE_CREATE, checking exact
entry identities and filesystem effects. All eighteen test bodies compile with
strict Windows GNU lint. Their genuine Windows execution now passes all eighteen
cases at `a3cbb911`, including actual mkdir and both collision races. Both native
platform jobs, Source subsets and actual TCP/STOP lifetime checks pass. Five of
