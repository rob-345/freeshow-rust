# Prepared import filesystem effects

`freeshow-import-effects` implements only final filesystem effects for the native, non-deserializable `MediaCommitPlan` from `freeshow-imports`. It does not interpret IPC, deserialize plans, access stores, choose library roots, change renderer events, or enforce the host's runtime generation. The trusted ordered library owner calls:

```rust
freeshow_import_effects::apply(&expected_imports_root, &prepared.plan)?;
```

`apply(&Path, &MediaCommitPlan) -> Result<CommitReceipt, EffectError>` is synchronous. The host must validate its frozen context and retain exclusive ownership of application library mutations during this call. `apply_with_config` permits tighter byte, entry, operation and timeout limits. `EffectError` exposes `code: &'static str`, `message: String`, bounded `rollback_failures`, and `rollback_omitted`; `Display` includes incomplete rollback details. Cancellation retains the preparation service's exact `cancelled` code. All other effect/validation codes use `import_` prefixes. Receipt fields describe installed relative destinations/bytes/SHA256, created relative directories (empty means the trusted Imports root), existing media count and deliberately unresolved media count.

The default limit is 128 MiB of aggregate installed media, 8192 plan entries and created directories, 32,768 recorded parent identities, 200,000 cooperative operations and a 30-second deadline (configuration cannot exceed 128 MiB/8192 entries/one million operations/120 seconds). Reads/writes use 32 KiB buffers and check `plan.ensure_current()` and work/deadline limits between chunks and filesystem operations. Work is sequential; no workers, detached tasks, retries of collisions or hidden queues are created. Source preflight hashing, copying and final installed-file hashing each read at most the bounded declared media bytes, plus one chunk to detect growth; the 128 MiB limit describes installed content, not total repeated validation I/O. Syscalls, disk flushes, kernel/filesystem stalls and an individual allocator call cannot be preempted by a cooperative deadline.

Before any final-root effect, the implementation requires exact native root spelling equality, normalized Unicode paths, the Projects/Templates/Overlays namespace, regular staged files confined below the private staging directory, matching expected source identity and SHA256, existing destination identity guards, and absent installation targets. All existing destination ancestors from the filesystem root are checked as non-symlink directories and their identities recorded. A missing trusted Imports root is allowed only under an existing validated parent. Private staging checks start at the trusted private staging directory itself and include every parent below it; system ancestors above private staging are not newly prohibited, allowing ordinary macOS temporary-directory aliases. Stage file opens on Unix use `O_NOFOLLOW | O_NONBLOCK` and revalidate path/handle identities, so static leaf symlinks and special files are rejected.

Only explicitly requested directory/install effects create directories. Raw text and plain `.freeshow` transports with empty effect plans create no Imports directory. Missing bundle references remain intentionally unresolved. Existing guarded media are read-only and revalidated before effects and again before success.

For each install, a private temporary file is created in the final parent, copied with hash/length checks, synced, and persisted with `persist_noclobber`; an existing destination is never overwritten. Parents, stage identity and absence are checked again at persist. Installed ownership is recorded immediately using the open temporary handle's identity captured **before** persist, rather than adopting an arbitrary file found at the destination afterward. The tempfile hard-link fallback's possible leftover temporary name is checked and removed. Unix parent directories are synced after install; Windows directory flush is not claimed. Final installed identity/hash and requested directory checks run before returning success.

On failure, rollback visits every journaled owned file in reverse order. It removes only a still-regular file with the same recorded identity, byte count and SHA256 under unchanged observed parents. Externally modified or replaced files are preserved. Newly created directories are removed only when the recorded directory identity still matches and `remove_dir` confirms emptiness; preexisting directories are preserved. Cancellation does not skip rollback: cleanup has its own bounded deadline/work budget, and remaining paths are preserved and reported if that budget expires. Detailed diagnostics are limited to 64 entries/64 KiB total, individual details to 4 KiB, primary messages to 8 KiB, all with UTF-8-safe truncation; omitted detail counts are explicit. These caps affect reporting only, not attempts to clean later journal entries.

This is **static path validation and observed identity checking**, not an OS capability sandbox. Path-based create/open/persist/unlink operations retain race windows if an external process renames/replaces ancestors between checks. A test deliberately moves a newly created parent just before persist: the changed identity is rejected, external replacement directories are preserved, and the moved temporary is reported through incomplete rollback rather than falsely claimed removed. Similar external races can prevent reclamation; the host's ordered owner excludes application mutations, not unrelated processes. A process crash/power loss can leave temporaries or a partially installed multi-file batch; there is no durable transaction journal or automatic crash recovery. Successful individual installs use no-clobber persistence, while a multi-file batch provides best-effort guarded rollback rather than one atomic directory transaction.

Unix identities include device/inode plus file length/mtime; directory identity uses device/inode. On Windows/non-Unix, the preparation contract supplies weaker file length/mtime metadata and directory checks use creation time. Replacement with indistinguishable metadata cannot be distinguished reliably; rollback conservatively retains a directory when creation metadata is unavailable. Existing-media guards contain no original content digest, so their original content cannot be reconstructed or checked against a new expected hash. Physical Windows/macOS execution is left to the coordinator's cross-platform CI; local checks run on Linux.

Focused tests use actual ZIP preparation through `ImportService`, not fabricated deserialized plans. They cover Unicode and multiple chunks, empty media, exact bytes/hash, unresolved references, raw/empty transport effects, source identity versus hash tampering, existing guards, wrong root and resource/deadline limits, late collisions and reverse rollback, cancellation after install and inside a partial copy, changed installed media at final validation, static stage/destination symlinks, same-byte inode replacement, preexisting directories, parent replacement limitations, and bounded Unicode rollback diagnostics with cleanup continuing beyond the diagnostic cap. No test sends network traffic or launches GUI processes. Standalone manifest/workspace/lock are temporary integration packaging; the coordinator owns workspace membership and removes the standalone workspace/lock as needed.
