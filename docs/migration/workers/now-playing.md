# Now-playing source foundation

`freeshow-now-playing` is a bounded pure planner for immutable FreeShow `2d94defcf98175e4f5c9504e7f4fd1d33c35c975` `src/electron/audio/nowPlaying.ts`. It prepares source text, metadata and ordered native effects; it does not read files, create tasks, call a codec, publish renderer events or claim that an effect happened. `IMAGE_BACKEND_IMPLEMENTED` is explicitly false. This slice contains only the new crate, its independent parity test and this worker document. Native main/IPC/library/audio/asset/bridge wiring remains future coordinator work.

## Source contracts

The actual source commands are `MAIN.NOW_PLAYING`, `MAIN.NOW_PLAYING_UNSET` and `MAIN.OPEN_NOW_PLAYING`. There is no source `NOW_PLAYING_SET` or public `GET_NOW_PLAYING_MEDIA_PATH` command. Set/unset/open return JavaScript `undefined`; no source success ACK is invented. `getNowPlayingMediaPath()` is an internal helper used by the server's `/nowplayingcover` GET route, which serves the cover if it exists or returns 404. The planner's `begin_media_path` prepares that internal path/ensure intent only; it does not implement an HTTP route or asset grant.

Source Audio paths are `getDataFolderPath("audio")/NowPlaying.txt` and `NowPlayingCover.png`. The source folder helper resolves the selected/default data root plus `Audio`, attempts directory creation and returns its path even if creation is logged as failed. It is not fixed app `userData/bin` or a guessed folder. The host supplies its captured, authorized Audio folder. POSIX and Windows joins, drive/UNC roots, dots and Unicode are handled lexically without filesystem resolution; POSIX backslashes remain filename characters.

Set awaits `music-metadata.parseFile(filePath)` without `skipCovers`, publishes `ToMain.AUDIO_METADATA { filePath, metadata: common }` if common exists, then calls Icecast metadata update. Parse errors/missing/empty paths yield null metadata and fallback text, without a metadata event. The artist helper selects a nonempty `artists` list in preference to scalar artist/albumartist/originalartist, filters truthy entries, trims ECMAScript whitespace, removes empty results and deduplicates case-sensitively in insertion order. Truthy malformed entries can throw after metadata publication; the planner preserves the tested partial-effect order.

Cover work happens before formatting: resolve Audio folder, check/delete an absent first cover, or create a native image from first-picture bytes, call `toPNG`, write the PNG, then get size and optionally resize/JPEG90. No decoded size/JPEG is fabricated before the cover write. Small covers retain the original compressed bytes for base64, even PNG bytes, but the source always labels the result `data:image/jpeg;base64,`. Empty buffers are truthy; empty/invalid image data can still produce an empty PNG and a base64 URI from the original bytes. Resize targets use source `Math.min`/`Math.round`, including a possible zero dimension.

Eight replacement passes are ordered artist/title/album/year/artwork path/artwork base64/duration/duration seconds. Each replacement value is resolved even when its placeholder is absent. Both artwork callbacks resolve/create the Audio folder unconditionally. Inserted later placeholders are processed by later passes; earlier placeholders are not revisited. JavaScript string replacement syntax `$$`, `$&`, `$\`` and `$'`is preserved, including prefix/suffix expansion. The caller's`data.format` is defaulted if falsy and mutated after each pass; a late error retains the partial mutation. Unknown fields are preserved and never interpreted as paths or effect instructions.

Duration uses source floor, signed remainder, padding and `toString`, including negative/nonfinite numbers and tested JSON coercions. A missing/null duration can throw during the final duration-seconds replacement even if that placeholder is absent. Native `SourceData::set_duration_number` preserves NaN/Infinity math for a trusted structured-clone number; its JSON payload cannot represent that number. A future host must apply only the returned format mutation to its original input object, retaining its real number/own-property values. JSON projections are not claimed as raw structured-clone identity.

Unset always updates Icecast to empty, resolves/writes the text file empty, resolves/checks/deletes the cover. It is not deduplicated. OPEN calls the real source `openInSystem(path)` behavior: check existence, `ToMain.ALERT "This does not exist!"` if absent, otherwise reveal the item in its folder. It does not launch a chosen executable or open the text in a chosen editor.

Source `writeFile` skips a string write only when the path exists and its source `readFile` UTF8 result strictly equals the string. A Buffer never strictly equals that string. `WritePolicy::SkipIfExistsAndSourceReadUtf8Equals` and `BufferAlways` make this explicit. The host must reproduce the source read/error/directory conventions and perform real IO, with its own bounded input policy. `Receipt::Done { success:false }` may mean a skipped write or a logged helper failure; it does not abort source continuation. A genuinely unsupported host operation uses `Receipt::Failed` with a bounded diagnostic and does not fake a successful write.

## Native API and accepted ownership

```rust,ignore
let context = Context::from_host(runtime_id, generation, data_path)?;
let paths = TrustedPaths::from_host(&context, platform, authorized_audio_folder)?;
let mut router = Router::new(context.clone(), paths)?;
let input = SourceData::from_payload(source_payload)?;
let media = TrustedMediaPath::from_host(&context, authorized_source_path)?;
let started = router.begin_set(input, media)?;
// Also: begin_unset(), begin_open(), begin_media_path().
let mut issued = started.effect;
while let Some(effect) = issued {
    let accepted = router.accept(effect.token)?;
    let receipt = host_execute_real_effect(effect.effect).await;
    issued = router.complete(&accepted, receipt)?;
}
let finished = router.take_result(started.operation)?;
```

Context, trusted paths, effect tokens, accepted tokens and receipts have no `Deserialize`/IPC surface. Context includes full runtime/generation/data path and a private run identity; each router has a separate token seal. An equal-looking foreign run/router cannot complete its effects. The media authority must exactly match the payload path spelling and context. `from_host` is not authorization by itself: coordinator code must derive it from a committed show/media/grant registry, accepted selection/drop/LOCATE or other real native provenance. Never call it as an arbitrary renderer-path grant. No executable or sink is selected by source data.

Four slots include active operations and completed-but-uncollected results. Every issued effect has a one-shot stage/serial token. After `accept`, cancellation only marks the operation; it cannot release the accepted slot or claim native drain. The future host must own the actual metadata/FS/audio/image operation and token through caller drop until real completion. This crate creates no worker/runtime to perform or drain that work. Incorrect receipt kinds reject while retaining accepted ownership and allow retry with the same borrowed accepted token. Duplicate/stale completions reject.

`cancel(operation)` invalidates unaccepted effects and returns any necessary private cleanup intent; accepted effects must really return first. A successfully created native image remains owned through errors/cancellation and requires `ReleaseImage` plus a true actual-disposal receipt before the result can be collected. A false/failed cleanup receipt keeps its token/slot accepted, allowing actual-owner retry; no timeout or guessed failure can release it. Dropping an accepted token without a real completion leaves the operation retained, rather than inventing cleanup proof. The host retains its bounded owner until it can supply that receipt. The planner does not provide generic transaction rollback: writes already accepted may have happened, just as source partial effects may precede failure.

There is no invented global current-content cache or source command deduplication. Concurrent set calls can finish metadata parsing in different orders; the host must preserve actual completion/effect ordering and account for accepted IO. Library switch/close requires native context validation before accepting or publishing effects, cancellation of unaccepted old plans, actual accepted-owner drain and image cleanup, then collection. The pure Context is a captured identity, not a live `LibraryService` lock. Use the actual ordered library IO authority for mkdir/write/delete and the existing source audio host for Icecast metadata; do not route the latter through a replacement fake sink.

## Metadata and image gaps

Existing `freeshow-audio::AudioService` implements READ_AUDIO_METADATA with `skipCovers`; absent pictures there prove nothing about a real cover. `Metadata::from_audio_reply(reply, Covers::Unknown)` therefore emits `ReadCovers` before metadata publication or destructive cover effects. Only a real complete cover receipt can supply `Covers::Complete` (including a certified empty list). All picture metadata fields are retained separately from compact `Vec<u8>` data; only the first picture controls the cover, while every picture belongs in the original metadata event. The host must restore `metadata.picture[i].data` as real Buffer/Uint8Array data before renderer publication; raw serialized planner effects are not source IPC payloads.

The audio adapter refuses native unsupported/resource diagnostics instead of silently converting them to a source parse failure. It also rejects a null `common.year`: actual music-metadata can produce NaN for an invalid YEAR tag, while existing native JSON projection loses it to null. Source would format `NaN`; guessing `Unknown Year` is incorrect. A real invalid-YEAR WAV test records this explicit unsupported case separately from matching cases. `PublishMetadata.json_projection_only` marks use of existing audio JSON: nonfinite/undefined/raw clone details need an extended metadata receipt/hydration before claiming full callback-value parity. Direct `Metadata::from_host` is for an actual source-shaped, bounded native receipt, not a claim that JSON can represent every JS object. Custom JS prototypes/functions, arbitrary Buffer-like objects and lone UTF16 surrogates are unsupported; non-BMP indexing of a malformed string-valued `unknownLang` is rejected explicitly.

No native image implementation is added. A host without a verified bounded decoder/PNG/JPEG backend must fail the image intent explicitly. Existing thumbnail canvas PNG validation is not Electron `nativeImage` parity and is not substituted. A future image owner must preflight compressed dimensions/pixels and allocation bounds before decoding; the planner's later source-ordered get-size receipt cannot itself bound a decoder's earlier internal allocation. The pure receipt policy caps reported pixels at 16,777,216, validates empty dimensions and bounds PNG/JPEG bytes. Native image resource handles must remain private and must actually dispose before `ReleaseImage` succeeds.

`tools/native-image-probe.mjs` ran against untouched packaged Electron 37.10.3 / FreeShow 1.6.7-beta.2 with a private profile and Xvfb. `fixtures/electron-native-image.json` records actual runtime versions, sizes, bitmap prefixes, PNG/JPEG lengths and hashes. A 2×1 transparent fixture yields the measured BGRA bytes; invalid/empty buffers yield size0/empty PNG. A 2000×1 fixture resizes to source target640×0 and yields empty JPEG. These are real source capability observations, not comparisons against an unimplemented Rust codec. The reproducible probe does not alter baseline source, install tools or write `node_modules`.

## Limits and checks

Per router: four retained operations, at most128 effect decisions per operation; source payload at most65,536 counted bytes/1024 JSON nodes/depth8; common metadata at most1MiB with the same node/depth caps; at most8 pictures with4MiB aggregate compact bytes and65,536-byte metadata per picture; native paths at most32,768 bytes; runtime ID at most256 bytes. Each intermediate formatted string is capped at1MiB before append, so replacement amplification cannot allocate unbounded output. There are eight passes and fixed recursion depth. PNG/JPEG replies are capped at4MiB. Diagnostics are capped at1024 UTF8 bytes. Caller-owned inputs/effects are distinct from planner storage; the future host needs the same whole-operation admission through accepted IO/resource disposal. No performance or hardware-delivery claim is made.

Eight Rust tests exercise native authority, foreign router seals, one-shot/wrong receipts, four retained results, cancellation before/after acceptance, actual image-cleanup receipts, cover-unknown requirements, path rules and resource/output amplification caps. Nine independent Node suites execute pinned original functions:95 source-shaped comparison cases,2 real WAV/music-metadata/native-audio files plus missing/corrupt files,9 controlled cover cases,4 nonfinite duration variants and10 source exceptions with matching partial traces. A separate real invalid-YEAR fixture is explicitly unsupported. FS/image boundaries are controlled and labeled; the OPEN helper and write-file comparison helper execute actual source. The real Electron image probe remains separate evidence. Source data/mocks are not copied reference algorithms.
