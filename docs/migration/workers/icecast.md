# Native Icecast sender

Coordinator integration adds this crate to the shared workspace/root lock and enables only its test CLI feature in source-test builds and strict core CI. The integrated 20 Rust tests and nine pinned-source Node suites pass without skips. Actual desktop AUDIO, Opus encoding and status delivery are still unwired.

This preparation branch owns only `crates/freeshow-icecast`, the new Icecast parity corpus/receipt, and this document. The temporary standalone workspace/lock must be removed when the coordinator adds the crate to the root workspace. No desktop, IPC, audio codec, root manifest, frontend, or CI wiring is included.

The oracle is the complete `src/electron/audio/IcecastSender.ts` at immutable revision `2d94defcf98175e4f5c9504e7f4fd1d33c35c975`. Tests transpile its actual declarations, replacing only import boundaries, random serial generation, and (for controlled tests) socket/clock/timer implementations. The real paired loopback comparison uses Node's actual TCP sockets and timers. Source hashes normalize CRLF. No third-party or production Icecast server is contacted.

## Host API and ordering

```rust
IcecastService::start(ContextId(library_epoch, session_epoch), Limits::default())
service.send_audio(context, encoded_opus_bytes, optional_js_config, cancellation).await
service.update_metadata(context, song_title, cancellation).await
service.disconnect(context, cancellation).await
service.take_events()                 // bounded, context/run-tagged observations
service.next_events().await           // notification-based; no host idle polling needed
service.retire(context).await         // closes admission and drains accepted effects
service.shutdown().await              // idempotent; preserves first terminal error
service.terminal_error()
```

One live service matches the original static sender. A second live service returns `owner_exists`. One dedicated OS thread owns one current-thread Tokio runtime, the socket, configuration, metadata, timers, Ogg counters, and command ordering. There is no blocking-pool or per-request thread/task. Tokio selects fairly between FIFO commands, connection progress, socket reads, and the connected silence timer. The socket has no periodic timer while disconnected; cooldown does not schedule reconnects. The separate lazy process-wide DNS thread has one active job and one pending slot. Report both threads honestly; the DNS thread is reused across service recreation.

The host must validate frozen context and serialize actual sink calls at the trusted audio boundary. FIFO order is the order commands obtain reserved channel slots and send; concurrently polled methods have no externally defined total order. Await each method in the order `processAudio`/`nowPlaying`/`CLOSE_PORT` establishes. Do not recreate/reset the sender for each target or packet. The previous audio-pipeline crate emits PCM encoder inputs, and its host must call the actual encoder first; this crate accepts **already encoded packets** and does not implement Opus encoding or prove codec availability.

The sealed `Receipt` exposes `context()`, `run()`, and `disposition()`. It has no public constructor, clone, or deserializer. `Written` means a complete page was accepted by the local TCP writer. `ConnectingDropped` means the triggering packet was dropped while asynchronous connection establishment is pending, including the call that starts it. `CooldownDropped`, `Disabled`, `Ignored`, `Updated`, and `Disconnected` distinguish other method outcomes. Neither queue acceptance, connected status, nor a receipt proves server authorization, audio delivery, decoder acceptance, playback, or hardware availability. There is no new successful IPC acknowledgement.

`StatusEvent.data` is the original `ICECAST_STATUS` payload. Pass only that field into retained frontend delivery. `diagnostic` is optional native error information, never an extra source wire field; it distinguishes `resolve_failed`, `resolver_busy`, `connect_timeout`, header/resource rejection, and `server_rejected`. Context/run fields are internal. Rust `None` is omitted by the harness's JSON serialization. The source object owns `error: undefined` on no-error events; an Electron-property-preserving bridge must restore that explicit own undefined if needed, not send JSON null. Filter events against the current host context and preserve their produced order, including false/false with an error followed by false/false without an error. The original socket `close` callback clears errors after `destroy()`.

Cancellation before admission rejects a command. Once its bounded slot is sent, dropping/cancelling the awaiting caller does not retract its owned socket effects. Admission reserves both a queue slot and byte permits before cloning packet/title bytes. Shutdown closes admission, waits for outstanding reservations, drains accepted commands, attempts EOS/half-close, drops the socket, and signals owner exit. No new socket event from a canceled old connection can be adopted: the one owned connection future/socket is dropped on disconnect/config change/retirement. OS connection callbacks are not separately spawned. New contexts require retirement/drain before starting a new service.

`Drop` requests the same owner drain but cannot synchronously report its result. The host must retain the service, await explicit retirement/shutdown, and surface `terminal_error`; accepted command effects do not depend on caller lifetime. Ordinary write/connect failures remain observable without claiming success. Teardown/resource/event-overflow/panic failures fence further effects and retain the first terminal error across repeated shutdown. A previously returned local-write receipt is not retroactively proof of a successful close. Final cleanup always drops the socket even if EOS or status publication fails. The final thread join may briefly wait for TLS/destructors after exit signaling; there is no zero-blocking OS-thread-exit guarantee.

## Source behavior preserved on the covered corpus

- Configuration uses the actual `icecast` truthiness, then `host || "localhost"`, `Number(port) || 8000`, `mount || "/stream.opus"`, `password || ""`, and `!!enabled`. A truthy primitive config therefore defaults to disabled. An absent/falsy config leaves the current stream untouched. Arrays/objects in `enabled` are truthy. Numeric strings, booleans, one-element arrays, unsigned radix strings, invalid numeric strings, and ECMAScript whitespace in `port` are covered. Primitive password coercion preserves UTF-8 Basic authentication bytes and primitive type identity for config-change detection.
- A changed effective config clears cooldown and disconnects before replacing config. Disabled config closes a connected/pending stream. Same-config reconnect attempts occur only on `send_audio` at least 3000 ms after the previous attempt. A failed connection's triggering packet remains dropped. Empty packets can start connections but produce no real audio page after connection.
- Header order and bytes, mount slash insertion, optional `Ice-Title`, authorization, `Expect: 100-continue`, and `User-Agent` match actual source output. The stream becomes connected after the local PUT header write; no HTTP success response is required before sending Ogg headers.
- Ogg uses the Xiph polynomial `0x04c11db7`, zero CRC initialization, little-endian checksum/serial/sequence/granule, exact lacing (including the zero terminator for a multiple of255), exact stereo OpusHead, `FreeShow` vendor, TITLE before ARTIST, and the actual `" - "` artist/title split and ECMAScript trimming. Titles without a separator retain their whitespace. Audio increments granule by960, regardless of packet contents/duration. Metadata changes create a new serial, reset page sequence/granule, emit BOS/head/tags without EOS for the previous chain, and reset starvation time. Repeated identical metadata emits no new headers. Disconnect attempts a zero-length EOS page at the current granule.
- The actual code uses **60 ms**, despite its stale1000 ms comment. Connected pacing ticks every20 ms and emits the exact `[0xf8,0xff,0xfe]` silence packet whenever time since last real packet is at least60 ms. A silent packet does not update the real-packet timestamp. Tests cover native59/60 ms and2999/3000 ms boundaries with a paused clock, controlled original source ticks, and real connected silence output.
- Server rejection tests remain substring checks on each received chunk, with409/`Mountpoint in use` precedence, then401/403/404 using the trimmed first CRLF line. There is no HTTP parser or cross-read response accumulation. Other status lines/data do not authorize/reject a connection. Original status deduplication and transient rejection-error clearing are compared.

## Bounds and explicit differences

Default limits:16 queued commands plus one executing command;256 KiB total retained packet/config/title bytes;16 KiB encoded packet;8 KiB metadata;16 KiB request header;64 KiB aggregate received response per connection;64 retained status events. The active command retains its byte permit through I/O. Config JSON has at most256 nodes and depth8. Host length is at most1024 UTF-8 bytes. Error text is at most2048 UTF-8 bytes. Hard maxima are64 queued commands,4 MiB retained bytes,65024 packet bytes,32 KiB metadata,64 KiB headers,1 MiB responses,1024 events. Public metadata/headers and queues are bounded before packet/title allocation; per-page CRC/lacing work is linear in the capped input. No image/video/filesystem operation is involved.

Connection DNS plus sequential attempts to at most8 addresses share a5 s default deadline (hard maximum30 s). Each write/half-close has a2 s deadline (hard maximum10 s). Active write/deadline work is not canceled by the caller or retirement; the host's terminal drain can therefore take active-write time plus bounded queued work plus EOS/close time. It is not bounded by a single write timeout. Metadata headers/EOS are small bounded writes. A stream can run indefinitely with bounded retained memory; total lifetime bytes are intentionally not capped. Continuous socket data is capped per connection. Event overflow is terminal rather than silently dropping status transitions; the host must drain events.

The process-wide `getaddrinfo` call cannot be interrupted, can allocate inside libc/system providers, and may outlive connect timeout/service shutdown. Timeout drops its reply; queued canceled jobs are skipped, and no additional resolver is created on recreation. The DNS queue has at most one active/one pending host. A stuck resolver makes later hostname attempts explicitly busy/timed out. Literal IPv4/IPv6 bypass it. No package downloads or custom DNS resolver are used. libc/NSS allocations and syscall timing are OS limitations outside the Rust buffer caps.

Explicit unsupported inputs include non-string truthy host/mount, object/array passwords whose JavaScript identity/coercion cannot be represented safely, own coercion functions, symbols/BigInt/accessors/proxies/custom prototypes, lone UTF-16 surrogates, fractional/out-of-range/infinite ports, radix numbers beyond128 bits, CR/LF/NUL host/mount/title injection, and configured limits exceeded. These return errors rather than imitating original exceptions after partial static-state mutation. Raw arbitrary encoded bytes are framed exactly on the supported corpus; they are not validated as Opus. More than65024 bytes cannot fit the original one-page lacing byte, and source throws; native rejects explicitly. Page sequence beyond signed32-bit source range and granule overflow are explicit resource failures.

Backpressure is deliberately bounded: the source ignores `socket.write()`'s boolean result and can queue indefinitely; native serializes finite `write_all` operations and returns busy/deadline errors. Incoming TCP chunk boundaries can differ from Node and influence its source substring behavior. Native performs a bounded graceful EOS/half-close whereas source immediately destroys after queuing EOS and may discard unwritten data. On a successful small loopback corpus both deliver identical raw framed bytes; this is not a network-loss guarantee. Native error messages for OS failures differ from Node's formatted `ECONNREFUSED`/DNS messages; diagnostic codes make the distinction explicit. Address order/fallback and IPv4/IPv6 selection may differ from Node's auto-family behavior. Keepalive enables a10 s idle threshold but kernel probe defaults/platform behavior are unverified.

Monotonic native cooldown/starvation time is robust to clock changes; the source uses wall-clock `Date.now`, so clock-jump behavior is not equivalent. Tokio skips missed silence ticks without burst catch-up; exact scheduling under load, write congestion, and event-loop stalls differs from Node. Native closes/fences a pending connect and stale old socket events; it does not reproduce the source bug where an old socket's delayed `close` callback can disconnect a newer static socket. Error clear is produced in the same owned teardown operation, whereas Node schedules a separate `close` event. Those interleavings and partial source exception state are excluded from parity claims.

Actual socket/DNS/keepalive evidence is Linux x86_64 loopback only. Windows GNU and macOS arm64 all-target Clippy are compile checks, not platform runtime, DNS, TCP timing, or packaging evidence. No TLS, Icecast server implementation, server capability negotiation, MessagePort, codec, external delivery, hardware, or desktop status integration is supplied. The host remains responsible for authorization, frozen context, admission ordering, repeated shutdown/error handling, and frontend status delivery.

## Reproduction

Use the pinned Rust toolchain and Node22.21.1. Reuse an owned target with `CARGO_BUILD_JOBS=2 CARGO_INCREMENTAL=0 CARGO_PROFILE_DEV_DEBUG=0 CARGO_PROFILE_TEST_DEBUG=0`; never use the coordinator's native target.

```sh
CARGO_TARGET_DIR=crates/freeshow-media-copy/target cargo test --offline --manifest-path crates/freeshow-icecast/Cargo.toml
CARGO_TARGET_DIR=crates/freeshow-media-copy/target cargo build --offline --manifest-path crates/freeshow-icecast/Cargo.toml --features test-harness
FREESHOW_ICECAST_BIN="$PWD/crates/freeshow-media-copy/target/debug/freeshow-icecast" node --test tests/parity/icecast.test.mjs
CARGO_TARGET_DIR=crates/freeshow-media-copy/target cargo clippy --offline --manifest-path crates/freeshow-icecast/Cargo.toml --all-targets --all-features -- -D warnings
```

The Node corpus defaults to root `target/debug/freeshow-icecast` (with `.exe` on Windows) for later integration. The executable requires the test-only feature. It caps JSON input/commands and is not a desktop entrypoint. `FREESHOW_ICECAST_RECEIPT` optionally writes the paired real-wire receipt. The committed `tests/parity/icecast-loopback.receipt.json` retains both actual raw headers and every raw page. Tests verify every raw CRC **before** serial normalization, then normalize only the ephemeral Host port and Ogg serial/checksum for comparison. Another test verifies the committed receipt's pinned source hash, unmodified raw CRCs, normalized pages, and statuses. The payload bytes are framing fixtures, not generated/validated Opus bitstreams.
