# Media bundling and copy preparation

This slice implements bounded native **preparation** for `MAIN.BUNDLE_MEDIA_FILES` and `MEDIA_FOLDER_COPY`, from immutable Electron source `2d94defcf98175e4f5c9504e7f4fd1d33c35c975`. Only private staged bytes are written. It does not install user media, create Shows/Media/hash folders, open folders, emit alerts, publish an IPC success, or implement the final effects executor. Shared runtime/IPC/workspace integration remains coordinator-owned.

## Observed original behavior

`responsesMain.ts` forwards BUNDLE to `bundleMediaFiles(data)` and MEDIA_FOLDER_COPY to `addToMediaFolder(data.paths)`. BUNDLE returns `undefined`, including after scheduling copies; receiveMain emits **no reply**. MEDIA_FOLDER_COPY resolves a boolean, and receiveMain emits that boolean. The boolean is `changed=true` as soon as any accessible source has an absent destination, **before** copyFileAsync. Copy failure does not reset it. Therefore a directory/read-permission copy failure can yield true without an installed file. Preparation never publishes this as a completed operation.

`bundleMediaFiles` enumerates Shows names in Linux synchronous readdir byte order, filters only final case-insensitive `.show` (even `.show` itself), reads with source UTF-8/BOM/replacement behavior, and uses actual parseShow/parseJSON semantics, including truncating to the first `}}]` on a JSON parse error. It accesses parsed `[1]`; it does not decrypt show content. Malformed/ciphertext-like input which fails JSON parsing is skipped with the source parse diagnostic. The crate does not assert that opaque content is plaintext or grant any new decoding/decryption authority.

Only these typed fields contribute paths, in this order:

1. Each show's `Object.values(media || {})`: `media.path || media.id`, then `Object.values(slides || {})` items whose exact `type === "media"`, using `src`.
2. `getStore("PROJECTS").projects` values, each `shows` entry with exact type image/video/audio/pdf/ppt, using `id`. Falsy type defaults to show, so it does not contribute. Folder/show/other types are skipped.
3. OVERLAYS values' media items, then TEMPLATES values' media items.

The implementation preserves JS truthiness, canonical integer-key ordering before other insertion-ordered object keys, and ordered Set path deduplication for BUNDLE. MEDIA_FOLDER_COPY retains its input duplicates; absent duplicate destinations are deterministically coalesced with explicit observations. It never scans arbitrary string fields recursively. Null/invalid array shapes that throw in the original are explicit native errors rather than successful empty bundles. Truthy non-string media paths are unsupported. Frozen stores are provided as full PROJECTS/OVERLAYS/TEMPLATES snapshots; PROJECTS includes its `projects` wrapper.

For each candidate, the original performs literal `mediaPath.startsWith(mediaFolderPath)` before filesystem access: a `Media-sibling` prefix can be skipped even outside the folder. No boundary check, normalization, case-folding, URL decoding or network fetch is added. Missing/inaccessible sources are skipped by F_OK. Parent folder IDs use **upath2.0.1** dirname/basename (backslashes normalized there), plus the original UTF-16 signed wrapping hash and `a`/`i` sign prefix. The final filename uses **Node Linux path.basename** on the original path, where backslashes remain literal filename bytes. Dot segments and UNC/drive-like strings retain those source naming quirks. Directory source paths normally become failed copy attempts; root/dot basenames that resolve to an ensured destination directory are observed skips.

The original creates the hash folder even when its destination already exists. Existing targets are skipped purely by access/existence, without comparing bytes. BUNDLE defaults to the data root's Media folder, independent of configured media sync. MEDIA_FOLDER_COPY uses configured sync root, otherwise the default Media folder. Default-root ensure occurs even for an empty MEDIA_FOLDER_COPY list; an empty BUNDLE returns before selecting/creating output or opening anything. An explicit bundle output path is honored only when frozen/approved by the trusted host.

BUNDLE schedules asyncPool(50) copies without awaiting and then immediately calls openInSystem when requested. Default Media was already ensured, but a missing custom root produces source ALERT `"This does not exist!"` **before** async copy folder creation. makeDir failure independently emits `"Error: Could not create folder at: " + path + "!"`, then original copy processing continues. This preparation returns an open-folder intent and guarded ensure effects; host must preserve those source alert/open phases. It does not invent a completed shell action.

## Trusted API and owner obligations

`MediaCopyService::{new,prepare,prepare_with_cancel,flush_released,shutdown}` and `COMMANDS` expose the two commands. `CopyContext::new(trusted_data_root, MediaSyncRoot::{Default,Configured}, approved_bundle_root, Arc<StoreSnapshot>)` freezes roots and store values per request. Roots are Unicode absolute strings, preserving raw configured/requested prefixes; generated paths use the verified POSIX contract. Renderer fields cannot replace the frozen sync/data roots. Missing approved bundle selection with actual candidates fails `invalid_context`. Unknown request fields are ignored without deep cloning. There is no Runtime/AppState/IPC dependency.

`PreparedMediaCopy` has private fields, no Deserialize, immutable getters, and a bounded manifest. It contains captured data/destination roots, ancestor safety identities, Shows listing/file guards, ordered typed effects, candidate/skip/duplicate observations, bounded diagnostics and **deferred** `NoReply` or `MediaFolderCopy {changed_if_effects_resolved}`. Installs carry sealed root-relative destinations, explicit absent target guards, private staged identity/length/SHA256, and source lstat/followed-file identities. Existing destination symlinks retain both link and followed-target guards. None of these fields is a renderer-supplied install command.

The future final owner must atomically validate the host runtime/library context, take ownership of the plan, and obtain a `CommitLease` via `pin_for_commit()` before reading staged bytes. `validate_commit_lease()` rejects foreign/released pins. One LIVE→PINNED CAS competes with expiry; a pin is single-use and cannot be cloned or deserialized. TTL/reaper/plan Drop cannot delete PINNED staging. After acceptance, `validate_commit_lease()` preserves physical ownership independently of the caller/request token; it does not itself authorize final writes. Pre-acceptance `ensure_current()` checks cancellation/expiry. Final host cancellation/context rules remain host-owned, including accepted effects surviving a dropped caller.

Before effects, validate the exact captured trusted roots, all ancestor/listing/source/staged/target guards, staged length and SHA256. Directory safety identities deliberately use device/inode/mode: unrelated entry changes (including private staging creation under /tmp) must not invalidate ancestor ctime. Shows listing guards and file identities additionally use length/mtime/ctime to detect relevant source changes. Parent containment must be anchored through directory handles, not inferred from lexical prefixes. No-clobber installation must retain ownership from the **preexisting opened staged handle**, then settle promoted metadata; rename/hardlink changes ctime, so blindly comparing old staged ctime after promotion is incorrect.

Host resolves Shows/default Media ensures, the early open-folder/ALERT phase, hash-directory ensures, existing skips and installs/ordinary attempt failures in the appropriate source phases. Ordinary confirmed copy failure still contributes true; resource/stale/cancel/guard/unsupported failures do not become a false successful acknowledgement. Host must also implement source file-mode/mtime/copy-error behavior during final installation; staged files are private mode0600, and raw inode timestamps from staging are not claimed to be final copy metadata. Do not publish the deferred result merely because staging succeeded. The flag is conditional on resolving the planned effects: if a directory ensure fails, the final owner must evaluate the source follow-up target-existence/attempt behavior (including root/dot directory aliases), rather than blindly returning a predicted false flag. Final no-clobber, rollback, alert receipts, crash consistency and owner integration are a separate slice.

## Fixed workers, leases and cleanup

There are **three fixed threads**: exactly two preparation filesystem workers plus one separately named staging cleanup worker. No per-request threads, spawn_blocking, Node runtime sidecar, FFmpeg, renderer generation or external runtime process is used. Job permits remain held until synchronous preparation returns, even after caller cancellation/drop. Admission checks cancellation both before/after acquiring permits and at the sender gate; cleanup-failure checks also repeat after permit admission. At capacity, preparation returns `copy_busy`, never an empty success.

Prepared leases independently bound queued work plus host-retained staging. The reaper owns TempDir and lease until cleanup has run. Plan/CommitLease Drop only changes an atomic state and nonblocking-enqueues a small message; it performs no filesystem cleanup on Tokio. Queue capacity covers all leased registrations/releases plus serialized fence/stop messages. `flush_released` fences already queued releases; it does not delete live plans. Failure closes further admission, is surfaced as cleanup_failure, and cleanup continues for other entries.

An unpinned plan expires after its configured TTL and is physically cleaned by the fixed reaper even if the host retains the Rust object (100ms scan interval plus cooperative filesystem time). Expired objects retain stale path strings but cannot be pinned/committed. Pin duration is bounded by the trusted final owner's own operation/deadline policy; pins remain count/byte bounded, and deliberately extend the staging TTL during accepted effects. A forgotten pin can retain only its capped lease, not unbounded additional staging.

Call shutdown in Tokio with time enabled **after draining accepted final-owner work**. Shutdown closes admission, cancels/drains preparation workers, checks is_finished before joining, then expires/cleans unpinned retained plans without waiting for their host Drop. If accepted pins remain it returns `copy_commit_in_progress`, preserves their bytes, and supports a retry after those pins drain. No-runtime shutdown closes/cancels and returns runtime_required; a later runtime call can drain. Drop alone cancels/closes and requests cleanup, but is not a synchronous terminal-drain guarantee.

## Resource envelope and limitations

Defaults: 2 worker slots plus 4 further admitted jobs, at most 4 retained leases, 256 candidate references before dedupe, 2,048 directory entries, 50,000 JSON nodes per bounded value, depth32, 32KiB paths, 2MiB per Show/16MiB aggregate Show bytes, 4MiB aggregate store strings/keys, 32MiB per media file/64MiB aggregate copied bytes, 4MiB serialized manifest, 500,000 checked operations, a 15s dispatch/queue/preparation deadline, and 60s prepared TTL. Hard configurable ceilings are 16 additional jobs, 8 leases, 1,024 candidates, 8,192 entries, 100,000 nodes/depth64, 32KiB paths, 8MiB per Show/32MiB aggregate Show bytes, 8MiB store strings/keys, 64MiB per media file/128MiB aggregate copied bytes, 16MiB output, 2,000,000 operations, 60s preparation and 300s TTL (TTL cannot be shorter than preparation deadline). Staged bytes are bounded by retained leases × copied_bytes, including cleanup still in progress.

Reads/writes/hash updates use 32KiB chunks and enforce declared/opened/actual file and aggregate byte limits. Metadata is rechecked through opened handles and lstat/followed paths after media/Show reads; changes fail stale_source_guard. JSON structure depth/token preflight runs before serde allocation, followed by bounded node/string validation. Directory/name/snapshot and manifest output budgets discard partial work on failure; a streaming borrowed manifest counter avoids allocating another JSON value just to count it. Diagnostics have at most16 fixed ASCII codes/errno/log flags (less than8KiB serialized), plus omitted count; no arbitrary exception/path text accumulates. Later files continue after ordinary source copy failures.

Bounds are cooperative: OS stat/access/open/readdir/read/write/flush/remove calls, one capped UTF-8/JSON decode, sorting, hashing/comparison and serializer scans cannot be preempted inside the call. A stalled filesystem can delay a worker, reaper, fence or terminal drain beyond nominal deadlines. Private staging contains a bounded number of generated flat files; cleanup uses TempDir's filesystem removal and has no hard syscall timer. External same-user mutation of private staging/ancestor trees is not made race-atomic here; final guarded effects must detect stale/tampered staged/source/target state and preserve external changes. Input special files are rejected before open and rechecked after it; O_NONBLOCK prevents a FIFO replacement from waiting for a writer, but does not make every device driver's open syscall preemptible.

Linux is the only verified filesystem/path backend. Windows GNU/macOS arm64 compile with explicit native unsupported_platform; pure Linux naming/hash tests still run everywhere against actual upath source with a POSIX path boundary. Non-Unicode entry/root names, lone UTF-16 IPC/JSON surrogates, nonfinite JSON number variants, unsupported truthy path shapes, special input files and unsafe symlink/non-directory destination ancestors fail explicitly. Existing live destination symlinks can be skipped; a dangling destination symlink is unsupported because source copy might follow it outside the trusted root. No recursive folder copying or protocol/network decoding is added.

Source asyncPool timing is deliberately not claimed: literal duplicate/colliding absent targets coalesce to first native source with DuplicateDestination observations, while original concurrent fs.copyFile can race/overwrite. A real Aa/BB parent-hash collision fixture demonstrates that original final bytes can come from either input. Native final no-clobber safety is stricter than source's check-then-copy overwrite race. Original reentrant currentlyBundling poisoning after malformed extraction exceptions is not reproduced as a permanent native service failure; those shapes receive explicit errors. No atomic global library/filesystem snapshot, exact concurrent source scheduling, batch/crash atomicity or full OS/format parity is claimed.

## Verification

Thirteen Rust tests exercise two-worker/queue saturation, caller drop, both shutdown/admission orders, no-runtime shutdown, retained TTL/cleanup, pin/TTL/planDrop/shutdown ordering, foreign pins/frozen root/store separation, opaque staged bytes/guards, existing/missing/prefix/duplicates, directory failure boolean, source symlinks/destination redirection/FIFO, mid-copy cancellation/tamper, file/output/JSON/deadline caps and bounded omitted diagnostics. Ten Node source tests extract actual immutable functions/constants/handlers using git show (CRLF canonicalized), invoke real controlled filesystem copies, and compare extraction/naming/source replies/staged bytes/hashes. They cover source JSON repair, malformed UTF8/BOM/ciphertext, integer-key order/truthiness, typed project/items filters, unknown-field exclusion, custom/default/sync roots, early-open ALERT, existing bytes, protocol literals, copy/read-folder permission failures and collision timing. Linux unprivileged evidence ran without skips; the dedicated denied-Show-folder evidence explicitly skips elsewhere, while ordinary tests on other OS assert unsupported native status. No official Electron/GUI is required for these JSON/boolean/undefined contracts.
