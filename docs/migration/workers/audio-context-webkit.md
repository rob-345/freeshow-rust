## Native policy and controlled boundaries

The standalone host is a real GTK3 WebKit4.1 view using installed WebKitGTK2.52.6. The fork pins Tauri2.12.4, tauri-runtime-wry2.12.2 and Wry0.57.0. I inspected the actual installed primary source: `tauri-runtime-wry/src/lib.rs:4737` creates `WebViewBuilder::new_with_web_context` without an autoplay override; `wry/src/lib.rs:851–881` defaults `WebViewAttributes.autoplay` to true; `wry/src/webkitgtk/mod.rs:403–409` sets WebsitePolicies Allow and `:432–434` enables WebAudio. The fork's main/output construction does not override these. The harness sets Allow/WebAudio explicitly and records actual settings. These are the relevant settings, not a claim to duplicate every Tauri setting or permission policy. WebKit documents [Allow](https://webkitgtk.org/reference/webkit2gtk/2.40.2/enum.AutoplayPolicy.html) as unrestricted autoplay and [WebsitePolicies](https://webkitgtk.org/reference/webkit2gtk/2.38.4/property.WebsitePolicies.autoplay.html) as the native policy property.

`build.mjs` bundles actual production analyser, routing manager, input capture, sidechain, multichannel, processor/SoundTouch, sender, channel recorder and effect modules. Twenty-two source files are recorded with hashes. Apart from the candidate analyser, loaded implementation dependencies must match immutable `2d94defcf98175e4f5c9504e7f4fd1d33c35c975`. Both variants load the pinned original channel/Main enums; current changes to those files are type-only and excluded from this control. The original analyser's normalized SHA256 is `ff000b9ddcd06eb88069a210abe09fb293e75a34e116bc702de0045768146eff`; the candidate's is `20630ed8e7f025ee664cb0bd7851e2daf5e80ba63c42fe10784d344168e361d1`. Actual retained PCM and SoundTouch processor files are copied into the private site and hashed.

The declared controlled boundaries are application Svelte stores, output-selection helpers (no configured output), AudioPlayer path lookup/check-loop initiation, microphone channel-count cache, native request/recording sinks, toast/filename helpers and language text. Routing's original deduplication function is extracted from its actual AST. No Web Audio, media, MediaStream, AudioWorklet, MessageChannel/MessagePort, oscillator, analyser, processor, routing algorithm or browser playback implementation is substituted. The native audio sink creates an actual MessageChannel and transfers its port through the exact source response; it retains bounded packet summaries instead of invoking the real Rust audio service or opening Icecast. Instrumentation delegates every constructor/resume/listener operation to the actual browser.

Each native view is ephemeral with private XDG paths; each run has a separate Xvfb/DBus session, loopback HTTP port and private PulseAudio Unix socket. The capture provider is an actual PulseAudio remap-source fed from a null-sink monitor by real `pacat`, with a deterministic8-second stereo WAV. It is a **software virtual device**, not a physical microphone or audible speaker. The trusted fixture permission callback allows audio-only requests; this does not prove Tauri permissions. Capture checks that the live track label is exactly `FreeShowVirtualAudioFixture`, keeping evidence scoped to that source. The loopback origin is a real secure context; production's `tauri://localhost` origin is a remaining integration boundary.

## Honest gaps and rejected earlier evidence

`MediaRecorder.isTypeSupported('audio/webm; codecs=opus')` is false for both variants on this installed WebKit. The original channel-recording path requires that MIME; its successful encoding/file-save path is **not certified**. No alternative MIME or fabricated recording success replaces it. Physical microphone/camera/display capture, hardware speaker output, actual multichannel hardware, final Svelte playback/capture UI, native raw AUDIO/Opus/Icecast delivery, file grants/custom-origin/CORS and full application/window shutdown remain unverified by this isolated harness. The original18 Node tests provide separate controlled2/4/8-channel and failure-boundary coverage, not physical hardware proof.

Failed/insufficient harness receipts are retained rather than overwritten:

- `full/` had12 passes and2 failed capture attempts: a monitor-only Pulse provider is filtered by WebKit, which reported0 devices/OverconstrainedError. This is not a candidate-only failure.
- `remap-capture/` and `remap-permission-capture/` discovered the actual software input but failed due to a test-host GI binding mistake. Installed GIR/header place `user_media_permission_is_for_audio_device` on the namespace, not the request object. The fixture was corrected; these are harness errors, not permission parity evidence.
- `remap-real-capture/` had live accepted tracks but initially used a `>-65dB` condition. Review caught that the source meter's silence floor is−60dB, making this insufficient signal evidence. All signal checks now require `>-45dB`; final capture also requires post-stop silence and actual ended tracks. Earlier live-track results are not counted as PCM success.
- `remap-signal-capture/` passed the corrected nonzero threshold; the final run additionally passes source-label confinement, post-stop cessation, module-once/pair comparisons and complete process reap assertions.

No CPU sample is collected. Concurrent root GUI work makes these functional runs unsuitable for performance comparison in any case. A shipping/performance decision still needs actual private full-fork retained UI/native integration, followed by separately coordinated immutable before/after release measurements.
