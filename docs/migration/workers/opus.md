# Owned Opus encoder capability

The original worker slice owned only the standalone `crates/freeshow-opus`, `tests/parity/opus.test.mjs`, small source-only oracle helpers/receipt under `tests/parity/fixtures/opus`, and this document. The coordinator owns workspace/runtime/audio-pipeline/Icecast/IPC/CI integration. There is no FFmpeg/Node runtime sidecar, network output, hardware, capture, or performance claim.

The source is immutable `src/electron/audio/processAudio.ts` at `2d94defcf98175e4f5c9504e7f4fd1d33c35c975` plus installed `@discordjs/opus`0.10.0 sources. Tests read the original with `git show` and normalize CRLF. Actual `processAudio` is transpiled and invokes the original native addon's actual constructor/encode methods through an observation wrapper; other sink boundaries are controlled. Native dependency code is not rewritten or simulated for codec comparisons.

## Source contract and capability

FreeShow constructs one global `new OpusEncoder(48000, 2)`. The wrapper selects `OPUS_APPLICATION_AUDIO`2049 and lazily initializes its native encoder on first encode/query. `processAudio` converts/resamples/accumulates in the existing audio pipeline and supplies exactly960 stereo PCM16 samples,3840 bytes, per call. The wrapper passes `MAX_PACKET_SIZE = 3 * 1276`3828 to `opus_encode`. No bitrate/complexity/FEC/DTX/CTL/reset is set by FreeShow. Its unused `BITRATE`64000 macro is not a configuration. The real addon reports automatic bitrate120000 before encoding and99000 after the first silence frame on both measured libraries. Native queries observe defaults; they do not set bitrate. Every successful call returns a newly owned packet, with continuous encoder state across frames, targets, Icecast config changes, and `CLOSE_PORT`/socket disconnects. The source catch logs encode/send failure and continues legacy routing without resetting the encoder.

Production uses cached `libloading`0.7.4 and a narrow public Opus C ABI, transcribed from the original bundled `include/opus.h`, `opus_defines.h`, and their integer types. Required production symbols are `opus_get_version_string`, `opus_encoder_get_size`, `opus_encoder_init`, `opus_encode`, and `opus_encoder_ctl`; the latter is called only for official read-only GET_LOOKAHEAD4027 and GET_BITRATE4003 requests. There is no arbitrary CTL API or opaque-struct layout guess. Evidence-only decoder symbols are feature/test gated. The trusted library is retained throughout calls and state use.

The interim version allowlist is exactly `libopus 1.3.1` and `libopus 1.4`. Other versions report `Unavailable(unsupported_version)` pending evidence. Matching a version string is an ABI/evidence gate, not executable authentication or proof of bit equivalence for every build using that version. Library selection is a native host decision: `LibrarySource::system()` uses Linux's standard `libopus.so.0` loader search; `unsafe LibrarySource::trusted_path(absolute_path)` requires a bounded absolute path without NUL and an explicit host guarantee that executable constructors/destructors and the public ABI are valid. The unsafe qualifier is deliberate; a claimed version cannot make an arbitrary executable safe. Neither type has a deserializer or renderer command. Do not accept paths from renderer payloads. The system capability reports the loader request label, not a resolved path or executable hash. The explicit paths and actual library hashes in the local receipt describe those measured builds only.

Default library discovery is explicitly unsupported outside Linux; a trusted host may opt into an explicit compatible library. Big-endian targets are unsupported. Windows GNU/macOS arm64 compile checks do not prove runtime loading, packaging, ABI/timing, or bit parity on those systems. No codec is downloaded, installed, silently substituted, or claimed bundled for distribution.

The owner queries positive encoder size, rejects more than512 KiB, rounds storage to16-byte aligned blocks, allocates/zeros that bounded memory, and initializes it with48kHz/stereo/AUDIO. Opus documents caller-owned get_size/init storage; `*_destroy` must not free such storage. Rust frees the allocation before explicit library close on normal disposal and reports close errors. Source constructor capability only means the wrapper exists; native capability is stronger because actual library/symbol/version/state initialization and read-only queries have succeeded. This startup difference and source lazy-init failure behavior are tested/documented rather than equated.

## API and host obligations

```rust
OpusService::start(ContextId(library_epoch, session_epoch), LibrarySource::system(), Limits::default())
service.capability().await // Available(NativeInfo) or explicit Unavailable(Error)
service.encode(context, pcm_3840_bytes, request_cancel).await // sealed EncodedPacket
packet.sequence()
packet.context()
packet.bytes(context)?     // checks matching live context before lending bytes
service.retire(context).await
service.shutdown().await
service.terminal_error()
```

Exactly one fixed CPU thread owns the encoder/library. There is no per-frame thread, blocking pool, Tokio runtime, periodic idle poll, or timer. It sleeps in a bounded channel receive when idle. Initialization/loading, every native encode, disposal, and library close run on that owner. Tokio supplies bounded channels, permits, and notifications only; a caller need not have a Tokio runtime to await shutdown.

The queue defaults to4 pending frames plus one active call, with8 retained-work permits shared by queued frames, active encoding, and successful uncollected/host-retained packets. Hard maxima are16 queue slots and32 retained permits. Permits and a queue slot are reserved under the same short admission lock used to close the sole sender, before copying3840 bytes. Output is capped at3828 bytes. Successful packets have no public constructor, clone, deserializer, or raw mutable buffer. Their work permit lasts until packet Drop. Retaining packets indefinitely consumes bounded quota and can make new work busy; shutdown does not depend on host-retained packets being dropped.

Admission is ordered by the trusted host's method calls/reserved channel sends. Concurrent callers have no source-defined order. A canceled/stale/closed request or unsupported frame is rejected before admission and does not advance state. Once admitted, caller cancellation/Drop does not retract encoding. The owner consumes it, advances actual codec state, and either returns a packet or drops the uncollected packet when its waiter is gone. Tests compare the next real encoded packets against original continuous-state output after an admitted caller is dropped. Ordinary negative encode errors do not reset the encoder; this continuation is controlled lifecycle coverage, not a claim that every native failure's partial-state behavior is characterized.

Integrate at the previous audio-pipeline's trusted accepted-frame boundary: encode in source order, submit each actual successful packet to the Icecast owner, then complete the pipeline's `EncodingOutcome` with the exact failed encode/send index when relevant. The accumulator removes a frame before encoding; neither encoder failures nor socket failures authorize restoring consumed PCM or resetting global encoder state. Encode every source-selected frame even when the Icecast owner will drop it while connecting, during cooldown, or because coerced config is disabled; skipping encoding would change later actual codec state. Keep the encoder across ordinary Icecast config/socket/CLOSE transitions. The Icecast owner's hardcoded idle silence packet does not advance this encoder; do not replace it by encoding zero PCM or reset state on starvation. No new successful IPC ACK is introduced. Capability is not proof of capture, socket availability, server acceptance, playback, or output delivery.

Retirement closes admission under the same lock, drains accepted CPU work, disposes initialized state/library on its owner, signals exit, and joins the actual thread. Concurrent shutdown callers wait for the same completed join and first terminal result. `Drop` closes admission and lets the owned worker drain, but cannot synchronously report cleanup; the host must retain the service and explicitly await retirement/shutdown. Retained packets immediately become stale when the context closes. The host must serialize final context validation and sink admission with retirement; lending bytes is not a claim that a borrowed slice cannot outlive a later context change. Finish already accepted sink effects through their own owners before retiring that context.

Source has one application-global encoder with no context retirement/reset. This service's frozen-context retirement is an explicit host policy boundary and destroys state; creating a new service starts a fresh codec. Do not reset it for target/stream/library UI changes unless the host deliberately retires the encoder context and accepts that distinction. Unavailable initialization is a truthful capability result; no fake encoded packets are produced. Native loading may remain unavailable until service recreation; there is no background retry.

## Limits and failure scope

Fixed buffers bound Rust allocations/linear conversion work:3840 input bytes,1920 native `i16` samples,3828 output bytes, and at most512 KiB aligned encoder state. The retained-work quota bounds in-flight/completed frame memory. Diagnostic messages cap at2048 UTF-8 bytes. Frame size/rate/channels/application/CTLs are fixed; arbitrary frame sizes, malformed typed inputs, native pointer inputs, float encoding, multistream/FEC/PLC/reset, and bitrate controls are outside this API. The test-only decoder caps packet bytes and5760 decoded samples/channel and is not a new production decode feature.

The default cooperative native-call budget is250 ms, hard maximum2 s. A late call is diagnosed **after return**, fences admission, and retains the first terminal failure; native C cannot be safely killed/preempted inside an in-process thread. Library loading/constructors, native initialization/disposal, OS dynamic-loader calls, scheduling, and final TLS/destructors also cannot be interrupted. Shutdown actually joins and can wait for them; there is no hard wall-clock timeout guarantee or claim that corrupt/malicious libraries are contained. Libraries must be trusted. Rust panic/contract/deadline/disposal failures become sticky across repeated/concurrent shutdown. Native negative encode errors remain explicit and can continue, matching source lifetime rather than silently resetting. Process crashes/OOM/segfaults are not caught by Rust panic handling.

Native implementations may use internal stack/heap scratch space; the queried state cap does not pretend to bound all allocator/loader/kernel memory. The verified source uses fixed frame/channel/complexity bounds; no untrusted dimensions or user CTLs can expand them. All source/native ABI calls on the supported corpus are tested on Linux x86_64. Allocation-failure/native-internal-error and all CPU/compiler combinations are not exhaustively reproduced. The original C++ wrapper does not check negative `opus_encode` length before `Buffer::Copy`; this slice rejects unsupported sizes before native calls and never reproduces unsafe huge-copy/partial-exception behavior. Original type-error and invalid-rate lazy-init branches are exercised in isolated test processes with valid-size buffers.

## Evidence and reproducible prerequisites

Local checks use pinned Rust1.99.1 and Node22.21.1. Linux has system `libopus.so.0`1.4. The npm package's native binary is absent (`require` fails) but its original sources are installed. The private oracle builder reads its actual `deps/binding.gyp` C source list and Linux/x64 config, compiles bundled Opus1.3.1 as a small private shared library, and compiles original `src/node-opus.cc` with N-API3 twice: once against bundled1.3.1, once against system1.4. Existing C/C++ compiler and N-API headers are required. The local `/usr/include/node` headers are newer than the pinned runtime, but only N-API3 is requested and actual methods run successfully in Node22.21.1. The build is an original-source local oracle, not a claimed official release-prebuilt binary. Each oracle/version runs in a fresh process to prevent ELF SONAME reuse from masking which codec was loaded.

The package's included CMake path is incomplete (`opus_buildtype.cmake` is absent) and can inherit this repository's Git version; the builder uses the original Gyp source list/config instead of editing dependency sources. Compiler flags/commands and selected source hashes are recorded in the private build receipt. Modern GCC warns about unused fixed-point paths also listed by upstream Gyp; the measured floating-point corpus and source/native comparisons pass. No source/dependency/node_modules/system package is modified, and no compiler/codec package is downloaded. Private oracle outputs total about732 KiB, excluding small receipts/configuration remnants.

## Shared workspace integration

The coordinator added this crate to the shared workspace, removed its standalone lock, and included its evidence CLI in the regular test and strict Clippy features. Linux core CI installs the declared runtime/build prerequisites and privately builds both original add-ons before running the full suite with `FREESHOW_REQUIRE_OPUS=1` and `FREESHOW_REQUIRE_OPUS_ORACLE=1`. The builder prefers headers bundled with the active pinned Node distribution, falling back to system N-API headers only when necessary. Other operating systems retain mandatory controlled ownership/source checks and explicit actual-codec capability skips; no compatible codec is yet packaged there. Production AUDIO integration remains a separate host/bridge milestone.
