# Native media-copy final effects

This slice applies the sealed preparations from `freeshow-media-copy` commit `c6f323ae9d2c7473968373fcd665ec105418bd9e`. It changes no IPC handler, store, shared manifest, frontend, or preparation implementation. The original oracle is FreeShow `1.6.7-beta.2`, revision `2d94defcf98175e4f5c9504e7f4fd1d33c35c975`. The differential tests retrieve its actual declarations with `git show` and normalize CRLF before TypeScript parsing. They execute the original handlers, `bundleMediaFiles`, `addToMediaFolder`, `createFolder`, `makeDir`, `copyFileAsync`, naming/hash functions and helpers against real controlled files; they do not replace their filesystem effects with a successful stub.

## Host API and required ordering

`freeshow_media_copy_effects::apply(TrustedCopyRoots { data_root, media_root }, &PreparedMediaCopy, &CommitLease, &owner_cancel)` returns a sealed `Receipt` or typed `EffectError`. `apply_with_limits` accepts explicit finite `EffectLimits`. The executor is synchronous and creates **zero** threads, runtimes, processes, shell calls, IPC commands or store writes. Its preparation dependency still owns its existing two FS workers and one private-staging cleanup thread. Tokio is used here only for the cancellation-token type; the feature-gated differential executable creates a runtime solely to drive actual preparation in tests.

The host must obtain `pin_for_commit()` while the preparation is current, move both the opaque plan and pin into its bounded ordered library owner, validate the frozen runtime context under its filesystem barrier, then call `apply` with the host's captured trusted roots. Root equality is exact at the original `OsStr` boundary. Passing roots read from an unvalidated request or simply treating plan getters as host authorization is insufficient. The executor additionally calls `validate_commit_lease`; a foreign pin is rejected before any final effect. There is no deserialization or renderer construction of plans/pins/receipts.

Receipts, manifests, private staging details and native failure phases are host-private integration data. Publish only the original supported command reply/ALERT payloads plus the host's explicit failure/capability path, after its context validation; do not expose this implementation protocol as a new renderer command.

After atomic owner acceptance, caller-drop/request cancellation and preparation TTL do not revoke the commit's staging. Only the separate owner cancellation token cancels accepted work. The real preparation pin keeps private files through final streaming and rollback, including if the plan is dropped. The host must drain accepted owner closures and drop their pins **before** `MediaCopyService::shutdown`; shutdown reports `copy_commit_in_progress` instead of deleting pinned data and must then be retried after drain. Rejected admissions must drop the owned plan/pin. No new unbounded blocking task or UI/Tokio-thread filesystem work is needed.

`Receipt::reply()` is `Some(bool)` only for `MEDIA_FOLDER_COPY`. It computes the source's actual attempted-copy boolean after resolving effects, including ordinary failures and the conditional dot/root alias case. It is `None` for `BUNDLE_MEDIA_FILES`, whose successful handler result remains undefined/no IPC response. Preparation is never acknowledged as completed copying. Source mkdir alerts are returned independently as exact strings for `ToMain.ALERT`. An ordinary failed attempt can have `Some(true)` and zero installed files; consumers must not label that as successful installation.

`installed()` records only verified promoted bytes with destination, length and SHA256. `failures()` gives a typed phase: the source-read failure observed during preparation, a final native copy error, an unavailable parent, or a missing directory-alias destination. Its optional OS code belongs to the indicated observed phase; inferred alias failures do not invent a Node errno. `preparation_diagnostics()` retains bounded original read/error diagnostics. A hard error has **no** original boolean response, retains prior observed alerts/failures/open intent in `error.observed`, and reports `rollback_incomplete` plus bounded cleanup diagnostics. The host owns logging, context-tagged publication and error/capability reporting.

For BUNDLE, `open_folder()` captures the original early decision after Shows/default Media creation but before candidate-directory/copy effects. A missing custom root produces `"This does not exist!"` even if later copies create it. Existence uses the **raw** captured root, preserving the `absent/../selected` quirk; generated destinations use the source's normalized Node join. `OpenDirectory` asks the host to call its shell implementation, including the source fallback to showing the item if `openPath` fails. `Missing` already has the source alert and must not be turned into a later successful open. Actual shell invocation is outside this crate and, when delivered after the ordered closure, occurs later than the Electron call; no exact shell/copy timing equivalence is claimed.

## Linux effects and bounds

Before the first final mutation, execution validates all captured destination ancestor identities, the Shows listing guard, original show/media link-and-followed-target metadata guards, existing target identities (including live symlink targets), target absence, every private staged regular-file identity and SHA256, and all declared byte/output limits. Media/video originals are **metadata-only** under the final owner; whole-file bytes come from the private stage. Open staged and directory handles are retained, with parent-chain checks before/after critical work. Raw source strings are not scanned for media, parsed as plaintext, decrypted or interpreted as network/file URLs.

Linux uses `O_PATH`, `O_DIRECTORY`, `O_NOFOLLOW`, fd-relative `mkdirat/openat/unlinkat` and `renameat2(RENAME_NOREPLACE)`. It consumes sealed relative paths; candidate naming helpers only match source order back to those sealed effects. It never chooses a renderer-specified arbitrary destination. Missing ancestor/hash directories are created through anchored temporary directories and no-clobber promotion. Directory mode follows the source's `0777 & ~umask` without changing the process umask. Copies stream into a new `0600` temporary inode in the target directory, apply the captured source permission bits, sync, and promote without replacing an arrival. Pre-existing targets remain untouched.

Ownership begins with a live temporary inode handle **before** promotion. A successful rename changes ctime, so post-rename validation compares that anchor's inode/content metadata and then settles its new ctime; it never adopts whichever inode happens to be at the destination. Installed content is hashed from that retained inode and guards are checked again before success. Linux metadata uses the same seconds/nanoseconds and device/inode/mode fields as preparation. There is no mtime/birth-time substitution for ctime and no wire Stats/Date projection.

Default limits: at most 1024 sealed effects and 1024 candidates, 64MiB declared installation bytes, 128MiB aggregate reads, 32KiB chunks, 8192 read chunks, 50000 cooperative operation checkpoints, 4MiB conservatively preflighted aggregate receipt/alert/error output, and 15 seconds. Hard configurable maxima are 4096 effects/candidates, 128MiB installs, 512MiB reads, 32768 chunks, one million operation checkpoints, 16MiB output and 60 seconds. Paths are Unicode, at most 32KiB and 64 components; preparation's usually smaller limits still apply.

Read accounting includes staged prevalidation, staged copying and installed verification: **three** complete passes. The default 128MiB read cap therefore admits at most 42⅔MiB declared aggregate bytes even though its separate write cap is 64MiB; larger valid preparations return an explicit `copy_effect_limit` before final mutations. A host may deliberately set 192MiB reads to admit 64MiB installs. Actual per-read growth is bounded by one 32KiB chunk. All loops, including partial/interrupted writes, check the work/owner budgets. Directory identities and descriptors scale only with the finite plan/path caps; low process descriptor limits can still produce a hard explicit I/O error.

Rollback walks a bounded journal in reverse after hard cancellation/resource/guard/collision/unsupported/I/O failures. It ignores the already-exhausted work deadline/token so every owned entry receives a cleanup attempt. An inode must still match its retained handle and settled metadata. Removal first moves it without clobber into a private `0700` quarantine, validates the anchor there, then unlinks. Nonempty directories containing external children are restored to their old name without clobber. Changed/replaced files, new target collisions and occupied directories are retained and reported; pre-existing/external bytes are never intentionally overwritten for rollback. A native ordinary copy failure cleans just its own partial temporary output and continues other candidates; source mkdir failures emit their independent alert on **each** candidate attempt, even when hash-directory intents were coalesced during preparation.

Cleanup detail strings are UTF8-safe, at most 16 entries / 16KiB aggregate (2KiB each), with a saturating omitted count. Hitting diagnostic capacity does not stop cleanup. Required source alerts are bounded by the preflight output budget rather than silently dropped. Error messages are capped at 2KiB. Unknown quarantines whose identity could not be established are preserved with diagnostics rather than adopted or deleted.

## Explicit limits and gaps

- Runtime filesystem effects are verified on local Linux only. Windows GNU and macOS ARM64 cross checks compile all targets/features with warnings denied; preparation/application return explicit unsupported-platform errors there. No timestamp, path, permission or filesystem primitive fallback is invented. Linux kernels/filesystems without `O_PATH` or `renameat2(NOREPLACE)` are unsupported; unsupported atomic rename is a hard error, with best-effort rollback if earlier directory work occurred.
- The source's check-then-`copyFile` race can overwrite an arrival and its 50 async copies can race each other. Native application is ordered, freezes preparation observations, coalesces absent duplicate/hash-collision destinations deterministically, and rejects late collisions/stale plans. It does not emulate those overwrite/timing races. Original missing/prefix observations remain the captured preparation decisions. Exact async callback/alert completion order across distinct files is not promised; native candidate order is deterministic.
- This is best-effort multi-effect rollback, not a batch-atomic filesystem transaction or crash-recovery journal. Power loss/crash can leave promoted files or hidden temporary directories. Files are synced; directory-entry crash durability is not guaranteed. Source creation can also leave partial ancestor directories after ordinary mkdir failure. Concurrent external parent renames, permission changes, changes to already promoted files, exhausted disk/descriptors, or quarantine-name collisions can prevent cleanup; `rollback_incomplete` and bounded retained-path diagnostics make that explicit. Some namespace races can move a colliding entry before a later anchor check detects it; no replacement inode is adopted as owned. Hostile code with the same uid/root privileges can access private staging/quarantine and is outside the ownership isolation claim.
- Deadlines/cancellation are cooperative. Filesystem calls, `fsync`, allocator/destructor work, random-byte retrieval and individual kernel operations are not preemptible. Cleanup has a finite object/depth/syscall-attempt bound but continues past the work deadline/token; it has no separate hard wall-clock guarantee. No process-tree/runtime cancellation is involved.
- Verified byte/mode scope includes real opaque and zero-byte files, Unicode, backslash/control-character names on Linux, ordinary directory sources, multiple files, live source/destination symlinks and readonly permission failures (the recorded local run used uid1000). Readonly rejection assertions run only for non-root Linux users; they are not permission evidence under root. Ownership, ACLs, extended attributes, sparse/reflink allocation, special files, exotic mounts, hostile same-uid actors and all OS variants are not claimed equivalent. Preparation's existing unsupported/capability/resource cases remain in force.
- Library-owner admission/context validation, final IPC/context tagging, shell delivery, root selection and terminal-drain integration remain coordinator obligations. This crate supplies no fake successful ACK or generated artifact for unimplemented host behavior.
