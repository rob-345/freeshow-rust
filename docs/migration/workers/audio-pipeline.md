# Native audio pipeline preparation

This independent slice implements planar Float32 stereo → interleaved PCM16 LE, the original stateful 48kHz resampler, source routing decisions and 20ms Icecast PCM accumulation. It owns only `crates/freeshow-audio-pipeline/**`, its new differential test and this document. Branch `agent/audio-pipeline` starts at effects commit `1ae29cf9340b2c554bd6e0259dde485d7f1ff6d8`; `agent/media-probe` and media-copy preparation `c6f323ae` remain intact. No shared/root manifest, retained frontend, existing crate, runtime or IPC handler was edited. The root `freeshow-audio` crate was inspected: it handles `READ_AUDIO_METADATA`/Lofty tags, with no duplication of this processing pipeline.

The immutable oracle is FreeShow 1.6.7-beta.2 revision `2d94defcf98175e4f5c9504e7f4fd1d33c35c975`. Tests retrieve and execute its actual `src/electron/audio/processAudio.ts`, `receiveAudio.ts` and `public/assets/pcm-worklet.js` using `git show`, normalizing CRLF. Adjacent NDI/OMT/Blackmagic/WebRTC/RTMP/Icecast/server/preload/IPC/capture boundaries were inspected to delimit intent semantics. AUDIO is a separate channel, not a new MAIN command; none of the prepared objects is an original successful IPC response.

## API and ordered host obligations

`AudioPipelineService::new(PipelineConfig, opus_available)` creates exactly **one** fixed CPU owner and no additional runtime, process, filesystem, network, device or cleanup thread. `opus_available` must reflect an actual host encoder capability; this crate neither discovers nor supplies one. `is_audio_enabled()` mirrors the source's encoder-presence flag, which the original capture lifecycle also uses to enable RTMP audio. It is not proof of device/network availability. Constructor use is runtime independent; async terminal shutdown explicitly requires a Tokio runtime.

`prepare(raw_view_bytes, &AudioMetadata, &SinkSnapshot, request_cancel).await` caps and copies exactly the supplied raw byte slice after bounded admission. The host's binary/typed-view adapter must extract the original view's `byteOffset/byteLength` without numerical reinterpretation, and validate its runtime context. The API does not parse a renderer command, recreate a MessagePort, or claim that JSON array values are a typed view. The differential tests execute the source's `toAudioBuffer` on Buffer/ArrayBuffer/typed/DataView subviews and serialized Buffer envelopes, then compare processing of their exact normalized bytes. Actual native binary IPC/view/envelope delivery remains host work.

`AudioMetadata` models receiveAudio's sample-rate/id coercions and optional Icecast value. `JsInput` distinguishes undefined, JSON values and IEEE numbers (including nonfinite values that JSON cannot hold). `SinkSnapshot::new(ContextId, ndi_keys, omt_keys, blackmagic_keys, output_stream_audio, webrtc_running, rtmp_running)` freezes the source registration/activity gates. Keys are original own registration keys, and flags are the original truthiness/running results. They do not assert that an NDI worker, hardware, stream socket or destination is usable. The snapshot has at most 64 keys per map, 1 KiB per key and 8 KiB aggregate key bytes.

The sealed `PreparedAudio` exposes ordered planar sink-call intents, a shared Icecast config and exact 3840-byte `OpusPcmFrame` views. Prepared/accepted/finished objects expose the captured `sinks()` snapshot through readonly getters, so the host can preserve lower-layer no-ops such as an empty Blackmagic registration map without re-reading live state. It has no public constructor, Clone or Deserialize. `accept(frozen_context)` consumes it into `AcceptedAudio`; stale context, request cancellation, shutdown or expiry prevents acceptance. No sink may be called merely because preparation returned. After acceptance the trusted ordered host must check `ensure_current(context)`, issue planar calls in order, then perform real encoding/sending frame-by-frame in order. Opus frame intents are **PCM inputs to a future encoder**, never fabricated Opus packets or delivery receipts.

`finish(&mut accepted, context, EncodingOutcome).await` accepts either all frames succeeding, or the index and encode/send stage of the first failure (with a bounded host error message). Foreign services, stale contexts, invalid indices and duplicate completions are rejected without advancing global state. A submitted completion survives a dropped awaiting caller. The result is sealed `FinishedAudio`, containing prepared legacy calls and a bounded source error diagnostic when encoding/sending failed. The host must dispatch/resolve those legacy calls before accepting/delivering the next packet's intents. The CPU owner can prepare the next queued packet after encode completion; it does not order external effects on behalf of a host that dispatches prepared objects concurrently. Actual sender exceptions, device queues, network pacing and delivery remain outside this crate.

Once accepted, request/caller cancellation does not revoke the known owner step. Dropping or timing out an accepted step with unknown partial sink effects terminates the pipeline explicitly (`audio_owner_abandoned` / `audio_owner_timeout`); it must not guess a consumed-frame count or resume with a false state. Already dispatched effects cannot be undone. The host must retain accepted work across caller drop, resolve its real first encoder/send failure, apply the resulting legacy sequence, then drain these closures before shutdown. `shutdown()` closes admission, fences queued/unaccepted work and wakes pending waits. If accepted/completing work exists it returns `audio_commit_in_progress`; finish it and retry shutdown. This is a host drain obligation, not a completed delivery claim.

There is one pending global transition at a time. Completed/expired host objects retain separate bounded buffer leases (default 4), so retaining old objects cannot cause unbounded output memory or bypass capacity. An expired unaccepted plan leaves source state unchanged; its quota remains held until that host object is dropped. Shutdown does not wait for such retained buffers. External cancellation is checked during admission, waiting for preparation, CPU work and acceptance. After a prepared object has been handed to the host, its drop/accept/deadline controls ownership: canceling its request token alone can leave the owner waiting until the host drops/accepts it or its bounded deadline expires. There is no periodic idle polling; the worker blocks on channel receive or a condition variable whose timeout is the current admitted packet's deadline.

## Source behavior retained

- Input is fixed stereo Float32 LE, planar left then right. PCM length is `floor(floor(byteLength/4)/2)*4`; extra bytes/odd float samples are ignored only by PCM conversion, while planar intents retain **all** original bytes/NaN payload bits. Nonfinite samples become zero, finite values clamp to ±1, negative samples scale by 32768 and nonnegative by 32767. JS `Math.round` half ties point toward positive infinity. Native rounding avoids `floor(x+0.5)`, whose intermediate rounding is wrong immediately below 0.5. No mono/multichannel behavior of the unused helper parameter is invented.
- The resampler uses the source's exact f64 expression/order, previous left/right values and phase. Its first interpolation uses previous samples even at phase 0. Rate changes to another non48k rate reset state. A48k or empty-input bypass does **not** clear an older resample state; a later call at that older rate resumes it. The output is fixed48k stereo PCM16. Direct helper tests also cover short/tail input, nonfinite/negative/underflow-invalid ratios and passthrough, comparing exact bytes and f64 phase bits.
- Receiver coercion is `Number(sampleRate)||48000` and truthy-id `String(id)` before the processAudio string check. This includes zero/NaN defaults, negative/Infinity values, JS numeric formatting, arrays and the precise JS whitespace set (including BOM, excluding U+0085). Plain JSON objects without custom coercion properties follow the ordinary source conversion. Unknown Icecast JSON fields and insertion order are retained.
- Latest Icecast config, resampler state and accumulator are **global across all targets/configs/ports**. Truthy config updates latch only for a nonempty valid packet; false/null updates do not clear the old config. Strict `enabled === false` suppresses Icecast preparation; enabled 0/null/missing and even other truthy config primitives still take the original encode path when an encoder is available. Actual `IcecastSender.sendAudio` may subsequently decide not to connect/send; no connection is claimed here. CLOSE_PORT/RESET_DECODER do not clear these globals in source; do not instantiate a separate native pipeline per target or reset it on those controls while claiming that behavior is retained.
- NDI target selection uses the original key membership gate. A matching OMT target still requests **broadcast OMT**. Any applicable legacy need calls Blackmagic regardless of target, then OUTPUT_STREAM only when enabled, WebRTC only when running and RTMP with the original target even if unrelated. These are source method-call requests; those methods may themselves no-op. Raw and converted buffers are immutable shared allocations across repeated intents.
- Icecast frames are 20ms/960 stereo samples/3840 bytes. Frames are removed from the slow-path accumulator **before** encode/send. A failure consumes that frame, retains later data (which may contain multiple complete frames), logs the source prefix `Could not encode Opus for Icecast:` and still permits legacy calls. `finish` preserves exactly that partial transition. The fast path with one exact frame and an empty accumulator has the same resulting state without copying frames. No Opus bitstream comparison is claimed.

## Bounds, failures and gaps

Defaults are 4 queued + 1 active admitted job, 4 retained output leases, 128 KiB raw input, 512 KiB conservatively counted prepared buffers, 64 Opus frames, 8 KiB metadata, 100000 sample/operation checkpoints, 250ms cooperative CPU work and a 2s total admitted/pending deadline. Hard maxima are 16 queued jobs, 8 retained plans, 512 KiB input, 2 MiB buffers, 256 frames, 32 KiB metadata, one million checkpoints, 2s CPU work and 10s total deadline. Metadata has at most 256 nodes/depth 8; target IDs at most1 KiB. Output diagnostic count is at most one source encode/send failure per packet, capped at 2 KiB, with fixed bounded error messages. Each input/job is capped before copying; resample expansion/aggregate sizes and frame counts are rejected before their large allocation. Shared frame/sink views avoid repeated buffer copies. Vec→Arc conversion, accumulator concatenation/residual copies and the single global accumulator have a finite additional transient/global allowance; the 512 KiB limit is a conservative prepared-buffer accounting cap, not a claim of an exact whole-process RSS cap. Default raw/payload/global/transient data stay below a small finite multiple of the queue/lease byte caps; thread stack/runtime allocator overhead is additional.

Practical positive resampling rates 8k–192k (including fractional rates) are covered. Other positive finite ratios are explicitly unsupported; ratio<=0/nonfinite/underflow passthrough follows source. Oversized expansion, frame count, metadata, buffers, CPU work, queued/retained capacity and deadlines produce typed failures, never successful empty audio. Native rejection leaves unaccepted state unchanged. The source can attempt larger/unbounded allocations or mutate state before a later allocation exception; those unsupported/resource variants are not claimed equivalent. Preserving every source's unbounded/malformed workload is outside this bounded slice.

Metadata support is JSON/IEEE scalar/array/plain-object data within the caps. Objects with own `toString`/`valueOf`, custom prototypes/accessors/functions/symbols/BigInt, unpaired UTF16 surrogates and radix integer coercion beyond 128 bits are explicitly unsupported/unrepresentable rather than guessed. The original may throw after latching a config for such variants; native hard rejection does not claim that partial source exception state. Constructor/host snapshot truthiness must be frozen correctly rather than inferred from arbitrary JSON in a renderer message.

Native conversion and state preparation are portable Rust and use explicit LE bytes; Windows GNU/macOS ARM64 cross checks are build evidence, not actual OS runtime or hardware validation. No source MessageChannel/port creation, native binary frontend delivery, browser AudioContext capture implementation, Opus encoder, Ogg framing/CRC, Icecast socket/reconnect/silence pacing, NDI/OMT worker, Blackmagic device queue, WebRTC output or RTMP process is supplied. Raw source worklet and transferred-port callback tests prove bytes/processing semantics only. No network/audio output, package/system installation, native/GUI/release build or runtime Node sidecar was used.

Deadlines/cancellation are cooperative between bounded sample/loop work and state checkpoints. Allocation, freeing and individual operations are not preemptible. Shutdown's notification occurs just before worker return; final join can still include thread-local/destructor work, with no zero-blocking guarantee. Host partial sink effects, stale context checks before each real call and terminal session replacement after abandonment remain explicit integration responsibilities.

## Checks and integration

The executable is feature-gated differential scaffolding. The Node test defaults to root `target/debug/freeshow-audio-pipeline` (Windows `.exe`); override `FREESHOW_AUDIO_PIPELINE_BIN` for isolated builds. Missing binaries fail rather than count as skipped parity. Temporary standalone `[workspace]`/Cargo.lock must be removed when coordinator adds the crate to the root workspace. Dependencies are serde/json, Tokio sync/runtime primitives, tokio-util cancellation and already-cached `ryu-js 0.2.2` for exact JS numeric strings; no audio/media/codec dependency was introduced.
