# Local media byte transport

Owned slice: `crates/freeshow-assets`, `src/frontend/rust/mediaUrl.ts`, and `tests/parity/local-assets.test.mjs`. Shared native startup, bridge, capabilities, existing Svelte helpers, and workspace manifests are integration work. No playback, protected-license, or thumbnail-generation implementation is implied by a successful byte response.

## Source contract and transport choice

The oracle is untouched FreeShow `1.6.7-beta.2`, source commit `2d94defcf98175e4f5c9504e7f4fd1d33c35c975`. `components/helpers/media.ts::encodeFilePath` is synchronous, preserves exact lowercase `http://`, `https://`, `data:`, `blob:`, and `freeshow-protected://` prefixes, and encodes local paths for Chromium's ordinary `file://` loader. Callers include images, video, audio, duration probes, and canvas helpers. `electron/index.ts` registers a separate privileged `freeshow-protected` protocol; it does not register a replacement ordinary file protocol.

`electron/data/protected.ts` provides the explicit source GET/HEAD/range contract reproduced here: full responses 200, first matching single range 206, unsatisfiable nonempty range 416, suffix ranges, case-sensitive/unanchored range matching, malformed ranges ignored, empty-file ranges ignored, `Accept-Ranges: bytes`, exact content length/range, `Cache-Control: no-store`, and inline disposition. Its unusual first-range and suffix-zero behavior is covered against the actual function, rather than replaced with a second JavaScript implementation. The source's 19 image/video MIME entries are loaded from a checked embedded table and compared with the actual source table. An additional 23 MIME aliases are checked against the packaged Chromium loader, including `audio/x-m4a` and `image/heif` as actually returned there. Additional image/audio extensions use explicit MIME types; unknown types use `application/octet-stream`. There is no content sniffing or codec detection.

The installed Wry `0.57.0` primary implementation, `src/lib.rs::RequestAsyncResponder::respond`, converts the response body into `Cow<'static, [u8]>`. An asynchronous callback therefore still requires a fully materialized body. A video-sized allocation would violate this slice's bounds. The transport instead binds an ephemeral IPv4 loopback port and streams HTTP/1 through Hyper. It does not bind another interface or run Node/processes to serve production requests.

The actual packaged Electron `net.fetch(fileURL)` returns requested range **bytes** with status 200 and no `Content-Range` in this environment. The native HTTP interface intentionally exposes 206 and `Content-Range`, following the application's explicit protected-protocol specification. The receipt records both, without claiming identical file-protocol headers. Full response bytes/MIME and valid requested-range bytes are compared directly with the packaged Chromium loader.

## Trusted host API

```rust
use freeshow_assets::{AssetServer, Config, Context, Control, NativeGrant,
    Protection, Provenance};

let assets = AssetServer::start(Config {
    allowed_origins: vec![actual_renderer_origin],
    ..Config::default()
}, captured_context.clone()).await?;

let result = assets.authorize(&captured_context, NativeGrant {
    source_path: exact_renderer_source_key,
    path: validated_native_absolute_path,
    provenance: Provenance::NativeSelection,
    protection: Protection::Plain,
}, Control::default()).await?;
```

`Context { runtime_id, library_generation, data_path }` has the same captured values as the library owner. Convert it explicitly at the host boundary. `NativeGrant` deliberately has **no `Deserialize` implementation**. Construct it only after a trusted committed-library snapshot, native dialog, native drop, committed locator outcome, or generated-thumbnail result establishes provenance. `Provenance` records which boundary the host used; it does not inspect or authenticate arbitrary renderer claims. There is no public authorize-path IPC operation, and HTTP accepts only opaque grant IDs. The JSON-lines binary is an independent trusted test host, not application IPC.

`source_path` is the exact string the retained renderer will pass to the synchronous encoder. `path` is its separately validated native filesystem path. Unicode, percent signs, spaces, hash marks, and file-URL spellings remain exact source keys; the registry performs no speculative decoding. Publish aliases explicitly when more than one source spelling is valid. MIME selection uses the authorized native path's extension, before canonicalization, as a file URL would. Initial authorization canonicalizes symlinks and captures device/inode on Unix or volume/file-index on Windows. Each request opens the canonical path and verifies its identity. Replacing a file requires a fresh grant. Retargeting an original symlink does not authorize its new destination. Same-inode edits are permitted; shrinking during a response produces a truncated/error stream rather than invented bytes.

`authorize_batch(&context, Vec<NativeGrant>, control)` admits a bounded, sequential batch. It returns `GrantBatch { grants, rejected }` with original failure indices. Ordinary per-file failures are explicit. Context change, cancellation, deadline, and shutdown abort the batch and revoke newly created grants. Pre-existing deduplicated grants survive rollback. `Control::new(deadline, cancellation_token)` is available for host cancellation; default authorization deadline is two seconds, with a hard ten-second per-file ceiling. Cancellation/deadline replies do not wait for a stuck OS syscall to return.

`activate_context(next)` accepts the current exact context or a strictly newer generation in the same runtime. A switch revokes all grants, cancels all accepted connections, and invalidates queued authorizations before later file work. `revoke(id)` cancels connections using that grant. Old URLs return 404. `shutdown().await` permanently closes admission, stops the listener, cancels connections, and drains the fixed file workers within its configured deadline. Dropping the last server handle also starts terminal cancellation. Bytes already delivered to a browser, its decoded resources, and bytes already buffered by the kernel cannot be retracted.

## Synchronous renderer integration

Create `createMediaUrlRegistry(getRuntimeContext, reportError)` in the trusted Rust bridge. Publish grants only after the associated context/snapshot has committed and before notifying retained UI consumers. Publish to every window role that needs those media resources. Late publications from an old context are rejected atomically. Clear/revoke registry entries when their native grants are revoked.

The coordinator may send a private host-to-bridge publication `{context,grants}` (not a renderer-to-host path request). Keep original source payload paths untouched. Split publication into batches no larger than the configured limit; bound both native grants and frontend retained entries. Prepare current-show/visible assets first, and surface `GrantBatch.rejected` plus explicit unregistered diagnostics for overflow or missing sources. Avoid recursively searching every JSON string named `path`: project roots, media IDs, network credentials, and import staging locations are not interchangeable native byte grants. Native host admission/context checks must cover preparation and publication so a library switch cannot retag old work. For already validated readonly `SHOW`/browse results, prepare grants on the independent assets workers and finish with a short current-context check; do not enqueue another ordered library-owner job behind ZIP compression. Mutating import/locator effects still commit before grant preparation. Keep one bounded host lease over preparation and publication, and propagate its cancellation token to `Control`.

At the very beginning of the existing local URL helper, before its `file://` stripping or URI decoding, add the host lookup:

```ts
const nativeUrl = mediaUrls.resolve(path)
if (nativeUrl !== undefined) return nativeUrl
// Continue the original encoder for bundled relative resources.
```

`resolve` returns remote/data/blob inputs unchanged. Unregistered native absolute paths/file URLs return an empty URL and an explicit `assets_unregistered` diagnostic. Bundled relative paths return `undefined` for the original encoder. Protected URLs remain separate and emit `assets_protected`; native authorization of protected grants fails explicitly. There is no renderer request that can turn an arbitrary local path into a grant. Registry publication validates opaque loopback URL shape, context, source-key bytes, and aggregate limits before replacing any entries.

The host must configure the actual renderer origin(s), including output windows and any intentional development origin; the default CORS allowlist is empty. The browser probe uses a disposable `data:` renderer with origin `null`; this is not a recommendation to add `null` to production configuration. Allow the selected loopback resource origin in any applicable CSP. Verify Tauri/WebKit mixed-content/private-network behavior on the real production origin during integration.

Canvas consumers must set `crossOrigin = "anonymous"` **before** assigning these HTTP URLs. Existing `helpers/media.ts::convertImagePathToIcon` creates an image without it, and `captureCanvas` currently sets it only when the original source string is nonlocal. Those two host-owned helper adjustments are required for canvas export. The packaged Chromium probe proves anonymous image canvas reads succeed and the unchanged no-CORS variant throws `SecurityError`. Ordinary image display and media playback do not establish canvas-read compatibility.

## Bounds and failures

Default limits are eight HTTP connections, two dedicated filesystem workers, eight queued jobs per worker, 16 KiB file chunks, 1,024 grants, 8 MiB accounted registry bytes, 128 files/1 MiB input per batch, 1 TiB per file, and 256 GiB per response. Headers are bounded to 16 KiB/64 fields; header timeout is two seconds and the complete connection/request timeout is 120 seconds. Shutdown timeout is two seconds. Configuration has hard upper bounds. There is no keepalive, global unbounded spawn, unbounded media queue, or whole-file read.

Each accepted connection owns one bounded task. At capacity, the listener itself attempts a small 503 response within 25 ms, using one additional accepted socket and a 1 KiB rejection buffer; it does not spawn another task. Extremely slow overload clients can receive a closed connection instead of a complete 503. The fixed worker queues return `assets_busy` on overflow. File open, canonicalization, metadata, read, and close occur only on those workers. Network futures hold lightweight file tickets, and released tickets are swept on worker admission or a 250-millisecond idle tick. Unix opens use `O_NONBLOCK` so a FIFO cannot block before regular-file rejection. Permission failures are surfaced, not treated as successful empty resources.

Hyper is configured with `writev(false)` and a bounded HTTP buffer. Its installed `1.12.0` `proto/h1/io.rs::WriteBuf::can_buffer` permits flattening only while below `max_buf_size`; a final frame can add one chunk beyond that threshold. In addition to these HTTP buffers, allow one current/read-result chunk per connection, a scratch chunk per worker, header buffers, and OS socket buffers. `status().peak_buffered_bytes` measures **producer response frames only**; it does not pretend to measure Hyper's copied flatten buffer, native worker scratch, allocator overhead, or kernel buffers. There is no media-sized allocation. Socket send buffers are requested explicitly; OS adjustment/accounting differs by platform.

HTTP validates the exact loopback authority, a random 256-bit per-run token, and random 128-bit grant ID. Grant URLs are bearer capabilities and should not be logged. Unknown grants/paths return 404; invalid authority 400; unapproved Origin 403 without CORS authorization; unsupported methods 405; resource limits 413; bounded IO overload/shutdown 503; IO deadline before headers 504. Midstream IO/cancellation closes the connection. Responses have `no-store`, `nosniff`, `Referrer-Policy: no-referrer`, and `Connection: close`. Only GET/HEAD and Range preflight are allowed. No credentials or arbitrary file-path query exists.

An OS/network-filesystem syscall can remain blocked despite cancellation. Admission remains closed, no replacement workers are spawned, and shutdown returns `assets_shutdown_timeout` after its deadline. The host must surface this failure instead of reporting a clean drain. Deterministic tests hold the actual IO adapter boundary to verify this case.

## Verification and remaining scope

Focused source/HTTP tests cover 138 source range cases, all 19 MIME entries with uppercase variants, actual GET/HEAD/range byte slices and headers, Unicode/reserved-character paths, empty files, authority/token/origin rejection, preflight, protected rejection, missing/permission/special files, file replacement and symlink pinning, registry/batch/response limits, slow headers, complete-request deadline, slow-reader overload, partial-transfer context/grant revocation, terminal drain, and the actual frontend registry. Five native tests hold worker execution to verify queue admission, immediate queued cancellation/context rejection, batch rollback preserving existing grants, shutdown timeout/terminal admission, and file/registry byte budgets.

The isolated actual-release probe records executable checksum/runtime versions and real file-loader responses, decodes a PNG pixel, seeks/plays a PCM WAV and a VP8 WebM, and verifies the canvas CORS behavior. `tools/fixtures/blue.webm` is a 763-byte generated one-second 16×16 blue VP8 clip, made with:

```sh
ffmpeg -f lavfi -i color=c=blue:s=16x16:d=1:r=10 -c:v libvpx -an -pix_fmt yuv420p -f webm blue.webm
```

The patterned `range.mp4` fixture tests byte delivery only and is deliberately not a valid video. No general codec equivalence is claimed. Linux tests are executable evidence; Windows/macOS library compilation checks validate APIs and conditional code only. Native runtime/network/filesystem/codec checks on those OSes, and real Tauri/WebKit playback/origin/canvas integration, remain host integration gates. Unknown extensions are not MIME-sniffed; some formats accepted by FreeShow's file picker may be unsupported by the target browser. Encrypted/protected media license/decryption, thumbnail generation, OS media facilities, and remote-download semantics remain separate gaps.
