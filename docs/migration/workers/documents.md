# Native document reads

This slice prepares `MAIN.READ_FILE` and `MAIN.READ_BIBLES_FOLDER` replies from the pinned Electron source `2d94defcf98175e4f5c9504e7f4fd1d33c35c975`. It does not write files, create directories, start external processes, parse scripture/JSON/subtitles, publish IPC, or change runtime/library state. The crate is now in the root/native workspaces; the [native file-read host](../native-file-reads.md) owns context, directory intents and callbacks.

## Source contract

`src/electron/IPC/responsesMain.ts` maps `READ_FILE` to `{content: readFile(data.path)}`. `src/electron/utils/files.ts::readFile` tests `existsSync`, then `lstatSync().isDirectory()`, reads the full buffer, and converts it with `Buffer.toString('utf8')`. Missing files, empty paths, embedded NUL paths, and ordinary directories produce `{content:""}` without logging. Dangling/looping symlinks also fail the existence test. A symlink to a directory passes lstat and fails reading with EISDIR on Linux, producing the same empty content with a logged error. Read/permission exceptions return empty content with a logged error. A literal BOM, newlines, embedded NUL content, and invalid UTF-8 replacement characters survive; this is not TextDecoder's BOM-stripping behavior. No trimming or parsing occurs. Request paths retain filesystem lookup semantics, including relative paths and unresolved `missing/..` components.

`readBiblesFolder` obtains `getDataFolderPath("scriptures")`, calls synchronous `readFolder`, and maps **every** name to `{path: path.join(bibleFolder,name),name: name.replace(/\.fsb$/i,"")}`. There is no extension/type filter, recursion, content read, deduplication, or Bible parsing. Directories, symlinks, and unknown extensions remain. Display names can be empty/duplicated; only a final ASCII case-insensitive `.fsb` is removed. Linux libuv scandir sorts raw UTF-8 filename bytes before decoding; this differs from UTF-16 and locale order. Permission errors EACCES/EPERM in `readFolder` return `[]` without logging; other read errors return `[]` with a log.

`getDataFolderPath` also calls `createFolder`/recursive `makeDir`. A failed mkdir emits `ToMain.ALERT` with exactly `"Error: Could not create folder at: " + path + "!"`, logs, and falls through to `readFolder`. An existing directory symlink causes a successful no-op recursive mkdir before listing. The new read-only crate elides that no-op, but does not execute missing/non-directory root preparation or manufacture successful creation.

## Host API and ordering

- `COMMANDS = ["READ_FILE", "READ_BIBLES_FOLDER"]`; unknown commands return `unsupported_command`.
- `DocumentContext::new(trusted_data_root)` freezes a Unicode absolute host-selected data root and derives its `Bibles` path using original POSIX join semantics. Roots are private with read-only getters. Never build this context from renderer fields. READ_BIBLES_FOLDER ignores its payload entirely. READ_FILE reads the request's string `path`, including selected paths outside the data root, as the source does; host request authorization remains independent.
- `DocumentService::new(DocumentConfig::default())` starts exactly two independent filesystem workers. `dispatch(command, payload, &context)` and `dispatch_with_cancel(..., CancellationToken)` return `PreparedDocumentReply { data, diagnostics, folder_intents }` or typed `DocumentError { code, message }`.
- `is_complete()` is false when a typed `EnsureBiblesDirectory { path }` intent remains. The path comes from frozen context. Its source-shaped `data: []` is **not** a completed directory-creation result. Host should ensure the frozen root under its existing ordered/context-validated filesystem owner before dispatch. Alternatively resolve the intent there, then repeat the bounded read after success. On mkdir failure, preserve the source ALERT/error/fallthrough-empty behavior; do not endlessly retry a known non-directory root or publish the pending reply as successful creation. This crate does not execute/acknowledge those effects. Missing parents and non-directory Bibles targets are tested pending cases.
- Before publishing any reply, host validates the captured runtime context again. This crate does not own runtime epochs, context tagging, renderer response queues, or a snapshot of externally mutable file contents. Frozen roots prevent payload/configuration cross-talk, not external filesystem changes. Source symlink following is retained for ordinary reads/listing.
- Await `shutdown()` in a Tokio runtime with time enabled before terminal exit. It closes admission, cancels work, drains permits, polls `JoinHandle::is_finished`, and only joins finished workers. Repeated shutdown is supported. Without a runtime it closes/cancels admission and returns `runtime_required`; a later runtime call can finish draining. Construction/drop require no runtime; drop alone cancels/closes but does not synchronously join or guarantee drain.

Diagnostics carry constant bounded codes/operation labels, optional Linux errno, and `source_error_logged`; source empty fallbacks remain successful replies with diagnostics. At most one diagnostic and one folder intent are produced per reply; no exception/path strings accumulate. Cancellation, timeout, resource rejection, unsupported encoding/platform/file type, malformed request, or worker failure return errors without successful empty data.

## Bounds and limits

Default limits are 2 worker slots plus 8 further admitted jobs, 32 KiB per request/trusted/emitted path, 8 MiB input bytes per read, 32 MiB serialized prepared reply, 10,000 directory entries, 500,000 operations, and a 10-second deadline measured from dispatch admission (including queue delay). Hard configurable ceilings are 32 further jobs, 32 KiB paths, 32 MiB read bytes, 64 MiB output, 50,000 entries, 1,000,000 operations, and 120 seconds. Validation happens before copying request strings/context. A semaphore bounds all accepted jobs; the fixed channel holds at most that total, including reserved worker slots not yet dequeued. Once both workers are active, at most the configured additional jobs can wait. Requests at capacity fail `documents_busy`, with shutdown taking precedence when observed.

Reads use 32 KiB chunks, validate declared/opened/actual lengths, and reserve one capped byte buffer. Lossy decode can require at most three UTF-8 output bytes per input byte. A counting writer checks aggregate JSON escaping/output without creating a second serialized JSON buffer. Directory names, joined paths and aggregate strings are bounded before appending records. An iterative merge over bounded index arrays checks cancellation/deadline/operations between comparisons and preserves raw byte order. Resource failures discard partial results.

Accepted work holds its permit until synchronous work actually returns, even if its awaiting caller is canceled/dropped. Both pre/post-permit and sender-gate cancellation checks prevent late admission after shutdown. Worker panics become `document_worker_error`. A dropped dispatch future cancels its child job; request cancellation can return to the caller before the worker has finished, but shutdown still drains it.

These are cooperative bounds. Filesystem access/stat/open/readdir/read calls, allocator activity, one capped UTF-8 decode, byte comparison, and serde's bounded string scan cannot be preempted inside the call. A stalled filesystem/device driver can delay a worker and terminal drain beyond the nominal deadline. Special files are rejected before opening and checked again after opening; O_NONBLOCK additionally prevents a FIFO path replacement from waiting for a writer. There is no atomic regular-file-only open primitive here: external path replacement can still occur between metadata and open, and arbitrary device open syscalls are not promised preemptible. Reads are not atomic snapshots and may observe normal concurrent file growth (strict actual-byte cap) or replacement. No per-request threads, spawn_blocking, GTK calls, runtime-side Node, or subprocesses are used.

## Evidence and unsupported scope

`tests/parity/documents.test.mjs` extracts the **actual pinned** function declarations, constants and both handler expressions from `git show 2d94...`, canonicalizes CRLF, transpiles them with TypeScript, and injects only filesystem/path/config/IPC boundaries. It uses real controlled files. The Node corpus has 299 UTF-8 fixtures (all 256 one-byte values; malformed/truncated/overlong/surrogate forms; 32 deterministic random sequences), BOM/NUL/newlines, Unicode names, missing/directory/symlink/errors, Bibles byte ordering/all entries/duplicate display names, frozen roots, no-op symlink-root mkdir, and actual source mkdir/ALERT behavior. Linux unprivileged permission evidence passes locally; that one evidence case explicitly skips on privileged/non-Linux hosts. Ordinary tests on non-Linux still run the source and assert native `unsupported_platform`, not invented successful replies. No official Electron package/app is required for this JSON/string-only IPC shape.

Twelve Rust tests cover fixed worker/queue admission, caller drop, both shutdown/admission orderings, in-progress shutdown drain, chunk/entry cancellation, deadline, frozen roots, pending no-write preparation, file/entry/path/output/operation limits, FIFO rejection, actual file growth, encoded JSON expansion and no-runtime shutdown. Linux tests execute; Windows GNU/macOS arm64 all-targets warnings-denied Clippy only establishes buildability, not filesystem parity.

Linux is the only verified native filesystem/path contract; other OS return `unsupported_platform`. Non-Unicode Bibles entry names return `unsupported_path_encoding` rather than imitating Node's lossy-name collisions. Non-Unicode trusted roots and unpaired UTF-16 IPC strings are unsupported (serde JSON strings cannot represent lone surrogates). Native special-file reading is unsupported even where Node would return content/empty success. The source's much larger Node string maximum is intentionally not attempted. There is no Windows/macOS ordering/path/permission claim, global file snapshot, root-creation integration, frontend/IPC wiring, or retained-response memory limit in this crate. Host transport and context integration remain coordinator-owned.
