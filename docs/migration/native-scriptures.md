# Native local scriptures

`MAIN.BIBLE` loads local `.fsb` files through the retained Svelte Bible reader. The native host supplies the selected library and actual OS Documents root; renderer fields cannot replace those authorities. The payload and callback remain the original `{name,id}` and source reply, with the original listener and current full library context. Preparation diagnostics are logged separately. See the [parser contract and source corpus](workers/scriptures.md).

Two whole-request leases cover preparation, ordered directory effects, a possible second preparation, and reply collection. The parser owns exactly two fixed filesystem/CPU workers. Existing Bible reads do not wait for the library write owner. Creating the selected `Bibles` directory runs on that owner after context and derived-path validation. A failed attempt publishes the exact independent source ALERT and continues with the original primary/legacy lookup. An admitted continuation owns its lease even when its IPC caller drops. Changing libraries cancels old read tokens; stale queued directory effects and replies are rejected.

Each parser preparation has its own cooperative ten-second budget, including parser admission. Waiting for an ordered mkdir is separate from parser work. The source makes two genuine loads, choosing primary versus legacy after the first result; the second read remains fresh. Legacy verse migration, truthy/falsy values, requested ID replacement and unknown fields retain source semantics. Limits deliberately reject oversized, pathological or unsupported input rather than inventing a successful Bible reply.

Shutdown closes admission, cancels reads, joins parser workers and drains whole host leases. Accepted directory effects still finish on their ordered owner. The application drains accepted library writes before terminal subsystem teardown. Parser shutdown and host drain timeouts are explicit and retryable; a terminal worker failure remains recorded through later shutdown attempts. These cooperative budgets cannot interrupt a blocked kernel filesystem call. They do not establish a hard global Quit deadline.

Linux Documents lookup uses GLib's native Documents directory, falling back to GLib's home directory. Tauri's `dirs` resolver can return no Documents directory for missing/disabled XDG configuration. The official packaged Electron 37.10.3 instead returns home in those cases. A [shared Rust resolver](../../src-tauri/src/documents_path.rs) and [packaged-application probe](../../scripts/migration/probe-documents-path.mjs) compare missing, explicitly configured Unicode/trailing-separator, and disabled XDG settings in private profiles without replacing HOME. Both runtimes' joined directory spellings are compared. The [archived receipt](baselines/documents-path-linux.json) records the official binary hash, native resolver hash and all three observed cases, including private-profile cleanup. Windows/macOS use Tauri's actual OS Documents resolver; corresponding packaged-Electron comparisons remain open.

Source provenance: [Electron's pinned Chromium/Node dependencies](https://github.com/electron/electron/blob/v37.10.3/DEPS), [that Chromium release's Linux Documents path](https://github.com/chromium/chromium/blob/138.0.7204.251/chrome/common/chrome_paths_linux.cc), and [XDG lookup](https://github.com/chromium/chromium/blob/138.0.7204.251/base/nix/xdg_util.cc). The runtime probe supplies the evidence for fallback behavior; a fallback inferred only from the outer Chromium function would be incorrect.

Native host tests cover exact primary/migration/missing callback values and listener/context, reads during a blocked write owner, ordered directory creation, legacy fallback after a failed mkdir, detached independent ALERTs, two occupied whole leases, terminal drain and an obsolete queued effect after library selection. Desktop coverage compares the complete original handler reply through `window.api`, then uses the retained local Bible drawer and its original navigation/display controls. Passing these scenarios does not certify the entire scripture feature.

Local integration verification passes **242 Rust, 254 pinned-Node and 20 frontend tests** (516), plus **77 Linux native host tests**. The rebuilt **139-step Linux editor workflow**, four native menu checks and actual file drops at both scales pass. Complete BIBLE replies also match during active real ZIP compression, with context/listener checks and no retained host requests. The retained drawer navigates books/chapters and sends a Bible cue to both live projection windows. The corrections retain source/native comparisons, match pinned Node's Windows file-open flag, and count actual live encoder leases. A deterministic test polls the real shutdown drain to prove reserved permits are excluded. Windows verification of these corrections is pending a fresh run; cross compilation is not runtime evidence.
