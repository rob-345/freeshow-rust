# Native documents and EXIF callbacks

The Rust host now routes READ_FILE, READ_BIBLES_FOLDER and READ_EXIF through bounded native services while retaining the Svelte request/callback API. The oracle remains FreeShow 1.6.7-beta.2 at `2d94defcf98175e4f5c9504e7f4fd1d33c35c975`. These are file-reading and metadata capabilities; complete scripture import, image decoding and file-format parity remain separate work.

## Concurrency and context

One `NativeFileReads` registry admits four whole requests across two fixed document filesystem workers and two fixed EXIF filesystem/parser workers. There are no per-request threads or subprocesses. Each request owns its captured runtime/library context and cancellation token until its final callback has been constructed. Both services have finite internal queues, byte/allocation/operation/output limits and cooperative deadlines. Library selection cancels obsolete reads; final context validation prevents old results from populating the new library. Reading a path does not authorize it for local media delivery.

Ordinary reads and existing Bible-folder listings bypass the ordered library IO queue. Missing/non-directory Bible roots produce typed preparation intents derived solely from the frozen native data root. The host resolves those intents on the existing context-validated IO owner, then repeats a bounded read after successful creation. A failed source makeDir independently publishes to the main window, even after its requesting caller drops. It emits exactly `Error: Could not create folder at: <path>!` as MAIN.ALERT, followed by the original empty folder response. It preserves an existing obstructing file. Accepted creation owns the whole admission lease even after its IPC caller drops; terminal exit drains library writes before closing services and awaiting active read cleanup.

READ_FILE preserves the original UTF-8 Buffer conversion, including a literal BOM, NUL content and malformed-byte replacements. It does not parse or trim the file. READ_BIBLES_FOLDER preserves source raw-byte filename order on Linux, final case-insensitive .fsb suffix removal, duplicate display names, unknown extensions, directories and symlinks. Renderer payload fields cannot choose this folder. Missing/permission/read errors follow the source's empty-value shapes with native diagnostics; resource/unsupported variants remain explicit errors. [Independent document evidence and bounds](workers/documents.md).

## EXIF clone fidelity

The parser follows the pinned exif@0.6.0 JPEG/APP1/TIFF behavior, static tag names, six groups and verified vendor quirks. It preserves numeric arrays, rational division and raw timestamp/text values. It does not infer decoded image pixels or substitute a different EXIF schema. Relative/literal paths keep source filesystem semantics. [Parser evidence, exact limits and deliberate unsupported cases](workers/exif.md).

A native-only event envelope describes clone values that ordinary JSON would lose: own undefined properties, NaN, positive/negative infinity, negative zero and byte buffers. The bridge accepts it only for a context-accepted MAIN.READ_EXIF event, validates every pointer/type/placeholder/budget before changing callback data, restores Uint8Array values, and then invokes the original callback. Invalid or obsolete envelopes never partially hydrate data or run that callback.

Own undefined fields can also affect property order. The parser and data-only source observer record the complete key sequence only for objects with omitted undefined fields. Bounded objectKeys metadata restores those properties in their original positions. The source comparison checks both actual values/types and recursive Object.keys order against structuredClone of the original handler on the generated corruption/field corpus and real dependency photographs. The earlier packaged Electron probe independently established its Uint8Array/undefined/special-number transport behavior; the native WebKit check exercises restoration in the actual retained browser.

Hydration is generated from trusted parsing, never accepted as renderer write authority. Its paths are restricted beneath exif, with a special root order record for the original `{id,exif:undefined}` shape. Prototype properties, missing parents, overlapping/conflicting writes, invalid numbers/bytes and mismatched key sets are rejected. Restoration admits at most 65,536 operations, 2 MiB of path units, 2 MiB of converted bytes, 65,536 bytes per buffer and eight object-order records of at most 1,024 keys. Parser output and component/tag bounds also apply before transport.

## Verification and limits

Native host tests use actual files and generated JPEG bytes, preserve Unicode/literal-percent spellings, payload/context/listener identity, exact byte metadata and missing own-undefined envelopes. File/EXIF replies complete while a controlled library owner is blocked. Bible tests exercise creation, duplicate names/directories, ignored payload roots, exact failure ALERT/fallthrough and whole-lease ownership after caller abort. Service tests additionally cover malformed UTF-8, real permission/FIFO cases, bounded worker/queue admission, parsing corruption/budgets and cancellation/shutdown.

The desktop probe runs four requests concurrently through the installed bridge: text, real EXIF, missing EXIF and the current Bible folder. A separate pinned-source process supplies expected values. The browser records Uint8Array identity, IEEE special values, own undefined fields and key order before WebDriver JSON serialization. It repeats those checks during the existing real ZIP workload, retaining the captured library context and requiring the owner still to be compressing. Receipts are stored in ignored `test-output-rust/desktop/file-reads.json`.

Document filesystem semantics currently require Linux. Windows/macOS EXIF parser builds and service tests do not certify every native filesystem/permission/teardown case; GUI execution remains pending. General scripture parsing/import, non-Unicode paths, unpaired UTF-16, non-regular files, unsupported malformed EXIF pointer coercions and empty/NUL path source hangs/crashes remain explicit gaps. Source-size/resource bounds intentionally differ from unrestricted Electron. Kernel filesystem operations cannot be preempted. EXIF shutdown can report a timed-out drain; document shutdown awaits admitted filesystem work. No replacement workers are spawned and no hard whole-runtime shutdown deadline is guaranteed. Passing correctness/concurrency checks establish no release application speedup.
