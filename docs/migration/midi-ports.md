# Native MIDI port ownership

The MIDI logic and port crates are now shared workspace members, using the root lockfile and default native backend. Core Linux CI installs ALSA development metadata and runs the same mandatory controlled/source suites and actual enumeration probe as Windows/macOS core CI. Coordinator integration passes all 19 Rust tests and 20 pinned-source/JZZ suites, strict workspace Clippy, formatting, and Windows GNU/macOS arm64 library Clippy. Native Windows/macOS execution still awaits the new complete CI run. These foundations do not yet connect the production IPC or hydrated renderer callbacks.

`freeshow-midi-ports` adds real ALSA/CoreMIDI/WinMM port enumeration, opening, sending and closing through midir 0.11.1. It uses the unchanged `freeshow-midi` foundation from `33cd1212` for source message construction, receive payloads, port bindings and MTC packets. No shared manifest, native host, IPC or Svelte file is changed. Native device delivery and complete MTC parity are not certified by controlled tests.

The immutable application oracle is `src/electron/utils/midi.ts` and `src/electron/timecode/MTC.ts` at `2d94defcf98175e4f5c9504e7f4fd1d33c35c975`, FreeShow 1.6.7-beta.2. New tests extract those actual functions using `git show` and run installed JZZ 1.9.5, whose JavaScript SHA-256 is asserted. Hardware boundaries use controlled JZZ virtual engines; JZZ's selector implementation, promises, packet constructors and message descriptions execute normally. Test wrappers convert VM arrays to the JZZ realm without changing their bytes.

## Host API and source mapping

```rust
let owner = Owner::new(runtime, generation, selected_data_path, run)?;
let service = MidiService::start(owner.clone(), context_cancel, Config::default())?;
let mut events = service.events()?; // exactly one event consumer
let ticket = service.begin(&owner, Command::Send(data), caller_cancel, deadline)?;
let reply = ticket.finish().await?;
// Consume events with context/run validation and original renderer hydration.
service.shutdown().await?;
```

`Owner` is a native-only constructor, with no `Deserialize`. Supply captured context and a fresh host run identifier. One service owns one immutable owner/run. On library replacement or terminal shutdown, cancel that owner, await actual drain, then drop its event stream before creating its successor. A timeout is not a completed drain. Do not create overlapping replacement services while an old handle owner is still running. The host must compare each event's owner/run against its current context immediately before renderer publication.

| Original behavior                     | Native command / result                                                                                                                                               |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET_MIDI_INPUTS`, `GET_MIDI_OUTPUTS` | `Command::Devices(Direction::{Input,Output})` returns `Reply::Devices(WireData)` containing only `{name}` entries                                                     |
| `SEND_MIDI`                           | `Command::Send(Value)` prepares source mutations, opens/reuses an output, then validates and transmits the actual three bytes                                         |
| `RECEIVE_MIDI`                        | `Command::Listen(Value)` consumes original `{id,input}`; incoming events contain the original `RECEIVE_MIDI2` `WireData`                                              |
| `CLOSE_MIDI`                          | `Command::close_inputs_field(data.get("id"))` preserves truthiness and JS property-key coercion, including numeric IDs; typed `CloseInputs(String)` is also available |
| `stopMidi`                            | `Command::Stop` closes ordinary MIDI bindings while retaining MTC's independent output/listener                                                                       |
| `setupMTCListener`                    | `Command::MtcListen(Selector)` returns a native listener handle; `MtcClose(handle)` stops that exact listener                                                         |
| `sendMTC`, `stopSendMTC`              | `MtcSend {selector,time_ms,framerate}` transmits eight ordered real quarter-frame packets; `MtcStop` releases its cached output                                       |

`Reply::Done` and `Diagnostics` are internal acknowledgements. Preserve the original void/undefined renderer response for send/listen/close; do not replace it with these native objects. Diagnostics should be surfaced/logged by the host. Device names and order come from the actual backend; missing/denied backend initialization yields `midi_backend_unavailable`, rather than claiming successful enumeration. The pinned original getter returns an empty list while its native dependency writes an ALSA error in this machine's denied-device case; the native diagnostic retains that distinction. If the host maps a diagnostic to the original empty UI list, it must also retain the diagnostic.

`Event::Midi` carries owner/run, a native listener identity and the exact source payload plus own-undefined/non-finite hydration instructions. Apply hydration only after current-context acceptance, using the existing foundation convention. `EventStream::recv()` rejects a revoked owner and skips queued messages whose listener has closed. Listener revocation publishes before a completed close acknowledgement. Initial-open callbacks are gated until registration; sequence fences prevent packets queued before a new MIDI/MTC listener from reaching that listener. Incoming messages share one physical connection when several source IDs listen to the same device, and the physical connection closes after its last MIDI/MTC reference.

`Event::Mtc` carries the ordered raw bytes, backend-relative microsecond timestamp and callback-time Unix milliseconds. The latter intentionally uses integer milliseconds like `Date.now()`. Feed it to the existing `MtcReceiver` with that captured clock sample on the host's ordered timecode stream. The host still owns `processFrame`, the shared `StatusGate`, timeline effects and timecode renderer publication. A single native MTC listener is supported per owner; close it before replacement. MTC output keeps its first selector until `MtcStop`, including the source's `24:0 || 1` FPS-code quirk.

Output handles stay open between sends. Packet validation deliberately follows successful open/cache publication, preserving source behavior on a bad channel/note/value. Input sentinel `"input"`, falsy inputs, duplicate/prototype-shadowed listener IDs, integer-key close order and unknown nonempty close-ID close-all behavior use the existing source-tested bindings. Specific close failure keeps the tracked binding for retry. Source close-all forgets failed bindings; native code instead reports its diagnostics and terminally retains any remaining actual handle on the owner until cleanup.

`Selector::{Undefined,Json,List}` reproduces JZZ's bounded JSON selectors, including name, numeric index, object name, lists and native undefined fallback positions. It preserves the surprising index-after-splice behavior: index `0` selects every remaining candidate, and candidates are tried until an actual open succeeds. It does not implement renderer function/RegExp selectors. Truthy close IDs that coerce to an empty key (for example `[]`) are explicitly unsupported because the foundation's typed empty-string close represents close-all. Prototype-shadowed output selectors remain explicit diagnostics, as in the foundation.

## Backend evidence and remaining MTC work

[midir's current API](https://docs.rs/midir/0.11.1/midir/struct.MidiInput.html) exposes real port metadata and owned connections. Its callbacks provide bytes and a relative microsecond timestamp; its close consumes the connection. Native calls run on this crate's fixed owner. No hand-written unsafe platform code or process-per-request backend is added.

The [pinned midir ALSA source](https://github.com/Boddlnagg/midir/blob/v0.11.1/src/backend/alsa/mod.rs#L818) checks `Ignore::Sysex` before extending its SysEx buffer. The installed CoreMIDI implementation likewise guards initial and continuing accumulation, and WinMM guards its SysEx copy before extending the message. This implementation explicitly sets `Ignore::Sysex` before native connect. Ordinary channel traffic, quarter frames, SPP, clock, start, continue and stop remain enabled.

Full-frame MTC SysEx reception is a remaining parity item. It cannot be enabled by removing the flag: upstream ALSA/CoreMIDI can assemble an unbounded segmented message before our callback sees it. A later narrow maintained-backend patch could bound assembly while admitting ordinary full-frame packets. Other SysEx and SysEx-dependent JZZ descriptions are also outside this slice. Native note labels preserve zero-velocity Note Off and controller 123's source quirk: JZZ describes it as `All Notes Off`, so the retained source sends `{type:"noteoff",values:{note:123,velocity,...}}` despite raw control status. All 128 controller descriptions are source-compared. For the actual complete packet `[0xb0,123,0]`, raw structured clone proves `note` is own `123` and `velocity` is own `0`; neither is undefined. For actual JZZ's truncated packet `[0xb0,123]`, the source object owns `velocity: undefined`, structured clone retains that own property, and JSON omits it. Native transport returns the omitted JSON field with `hydration.undefinedPaths: ["/values/velocity"]`. The future host must assign that own undefined property after context acceptance and before invoking the original callback. The new test independently asserts raw source own-property evidence and the native data-only projection; it does not certify an integrated hydrated renderer callback.

Backend names are passed unchanged. Jazz and midir naming, OS enumeration ordering, physical hotplug identity, exclusive-open behavior and driver close side effects are not assumed equivalent without devices. Native enumeration refreshes when requested; the original `JZZ().info()` may retain an earlier engine snapshot until JZZ refreshes. Device disappearance/name change is checked on the owner at most once per second and faults the run. IDs/names reused for a different physical device cannot be conclusively distinguished by this metadata check. Backend close acknowledgement means midir returned; some platform implementations discard underlying native close error codes, and hardware drain is not certified.

## Bounds and lifecycle

There is one fixed command/handle thread. midir may additionally own one input thread per open ALSA input, capped at eight physical inputs. Physical outputs are capped at sixteen; logical MIDI/MTC-output bindings share the foundation's 32-binding cap, checked before opening a provisional handle. One MTC-input binding is additional. There are no per-request threads or spawned blocking tasks.

Command admission is immediate and bounded at 32 queued/in-progress operations. Typed JSON is limited to 1,024 nodes, depth eight and 64 KiB of string/key/scalar work before parsing/cloning into candidates; native selector lists have at most 32 parts. Port enumeration has a 256-entry and 64 KiB aggregate name/ID limit, with individual names/IDs capped at 4 KiB. midir internally allocates its OS enumeration vector: a pre-count and post-check bound the accepted result, not all upstream allocations during a concurrent OS change. This upstream race/allocation boundary is explicit.

Callbacks check owner/physical gates and copy at most twelve bytes into a 256-entry raw queue using nonblocking submission. They perform no filesystem/JSON work, variable-size packet allocation, blocking IO or awaiting. The owner transforms/fans out events to a separate 256-entry bounded queue; source IDs are bounded JSON, so retained event data is bounded as well (up to roughly 16 MiB for maximal IDs). A closed/slow consumer, raw overflow, unsupported oversize callback or lost device faults the owner, revokes further callbacks/events and closes its actual handles. Failure is visible in status/shutdown; reopen requires a new owner after drain, with no silent note loss followed by apparent success.

Caller cancellation/deadline is checked before admission and when the ordered owner accepts queued work. After a backend operation starts, dropping its requester never detaches that operation or prematurely releases its admission lease. Accepted IO finishes on its actual owner; an accepted listener remains until its authorized close or context cancellation. Context cancellation still prevents a completed late open from proceeding to a new send. A native send already inside an OS API cannot be undone. No hard execution deadline is claimed for an uninterruptible driver open/send/close.

Default idle cancellation polling is 100 ms (configurable 1 ms–1 second); command/callback submission unparks the owner immediately. Shutdown closes admission and event gates immediately, drains/joins actual owner work and backend callbacks, then reports completion. Its default wait is five seconds (maximum 30). A blocked backend operation reports `midi_shutdown_timeout`; the same owner retains the handles and supports a later shutdown retry. Final service drop requests closure; hosts must await shutdown and retain the owner if it times out. Diagnostics are bounded to 1 KiB each and close diagnostics to 32 entries.

## Focused validation

Thirteen Rust tests cover actual owned deferred open/close, requester drop after acceptance, queued cancellation/expiry, 32-command overload, blocked shutdown/retry, exact message bytes, physical sharing, specific close-failure retry, terminal close-all failure cleanup, MTC independent references, stale context/callbacks/already-queued events, actual queue overflows, device disappearance, numeric close IDs, reservation before physical open at the logical binding cap and pre-registration callback sequence fences for MIDI and MTC.

Eleven immutable-source/JZZ suites cover 212 selector cases, eight ordered source/native scripts, 30 sent packets, 148 received WireData projections, two device-list projections, one deferred actual JZZ open and one real native enumeration probe. This covers all 128 controller labels, failed candidate fallback/retry, duplicate IDs, source close order, the MTC selector cache and source packet errors after opening and null-listener rejection before opening. The reference side uses actual JZZ virtual engines and real deferred thenables; no hardware send is implied.

[The recorded Linux probe](../../crates/freeshow-midi-ports/fixtures/native-linux.json) contains the executable hash, original source/JZZ hashes, dependency versions and actual stderr/results. There was no successful hardware/loopback open, send or delivery. No permission, module, device, package or system setting was changed.
