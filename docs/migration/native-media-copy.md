# Native media copy and bundling

`MAIN.MEDIA_FOLDER_COPY` and `MAIN.BUNDLE_MEDIA_FILES` now use bounded Rust preparation and guarded final effects, retaining the Svelte interface. This integration is partial and currently supports Linux filesystem effects. Windows/macOS return an explicit unsupported-platform error. Full parity remains incomplete.

The preparation and effect contracts, source comparisons and limits are documented in [media-copy preparation](workers/media-copy.md) and [final effects](workers/media-copy-effects.md). The immutable Electron baseline is `2d94defcf98175e4f5c9504e7f4fd1d33c35c975`. The [shared original-handler oracle](../../tests/parity/lib/media-copy-oracle.mjs) executes those actual TypeScript handlers and helpers with real Node files, preserving their asynchronous copy completion before comparisons.

## Ownership and ordering

Two whole-request leases cover snapshot capture, preparation, queued/active installation, cleanup and completed-but-uncollected replies. Accepted continuations retain ownership after an IPC caller drops. Terminal shutdown closes admission, cancels preparation, drains those leases, then joins the fixed preparation and cleanup workers. A timeout retains ownership for retry; it does not kill blocked filesystem calls. A real worker-panic test verifies closed admission, complete owner cleanup and a sticky failure on repeated teardown.

Ordinary media copies obtain the committed media-setting/context snapshot without filesystem work or IO-queue admission. Reading and staging the actual media therefore runs independently of a blocked library owner. Bundling captures bounded PROJECTS/OVERLAYS/TEMPLATES bytes together on that owner, then scans shows and stages media outside it. Original store bytes, configured media root and full runtime/library context are revalidated before final writes. Concurrent store/configuration changes reject the frozen plan rather than silently adopting newer inputs.

Media batches prepare and install in order. Two simultaneous plans for one absent tree would otherwise reject directories created by the preceding plan. A bounded batch owner prevents that conflict while preserving directory/source guards. Other native services and presentation control remain independent. The underlying preparation service has two fixed file workers; this host does not claim simultaneous preparation of multiple media batches or a measured copy speedup. Future parallel batches need proven coordination of shared directory effects.

The opaque preparation is pinned **before** final IO admission. Once accepted, that closure owns its staging through installation, even if the caller disconnects, its original token expires or terminal shutdown starts. The ordered closure applies effects with its own owner token, publishes already observed source ALERTs, and only then releases the pin. Cleanup is fenced on every exit before releasing whole-request admission. An already accepted effect finishes; a stale context, changed input/store/root or unaccepted canceled preparation cannot install files.

## Retained behavior

`MEDIA_FOLDER_COPY` replies with the original boolean, listener ID and current context. Existing destinations retain their bytes; source `changed=true` behavior for attempted ordinary failed copies remains in the effect receipt. Bundling has **no successful IPC callback**. Missing-folder/error ALERTs are independent native events, without an invented correlation or completion channel. A missing-folder open intent already contains its ALERT and is published once.

Default BUNDLE targets the library's `Media` directory even if media sync is configured. A custom bundle destination must equal the already committed native media-folder setting; renderer payloads cannot authorize arbitrary new roots. Native folder launch uses the existing Tauri opener on the ordered owner and falls back to revealing the item if opening fails. Platform launch can complete asynchronously; no operating-system file-manager readiness or descendant-process drain is claimed. The source launches its folder before asynchronous copies; the host publishes its captured open decision after bounded effects, an explicit timing difference.

The bridge snapshots copy/bundle payloads at send time and waits for preceding media-setting writes. Copies do not join the general SAVE mutation queue; version queries and live output messages remain independent. The native command accepts the main window only. A private read-only status command exposes bounded ownership and failure state without granting filesystem authority.

## Bounds and remaining work

IPC is limited to 1 MiB, listener IDs to 256 bytes, captured media configuration to 1 MiB and the three raw bundle stores to 4 MiB aggregate. Private store reads require opened regular files, use nonblocking Unix opens, bound actual bytes and reject non-object stores. The preparation/effect contracts separately bound candidates, input/staged bytes, traversal, reply size, operations and cooperative deadlines. These accounts are not whole-process RSS measurements. Admission/batch/IO waits and nonpreemptible OS calls have no hard completion guarantee.

The host tests cover exact opaque bytes, Unicode/hash paths, repeated destinations, bundle store/show references, original callbacks/no callback, configuration/store/library changes, two admitted callers, accepted caller Drop and shutdown, one missing-open ALERT, and preparation reading before release of an actual blocked IO owner. A source mutation after that preparation is rejected at final installation. Scripture completed-but-uncollected reply ownership also has a separate regression.

Windows/macOS effects, custom bundle roots outside the committed setting, unrestricted source sizes, parallel media batches, original 50-copy asynchronous scheduling/overwrite timing, hard kernel cancellation, durable crash recovery and whole-batch atomicity remain open. Local integration passes **270 Rust, 279 pinned-Node and 20 frontend tests** (569), plus **89 Linux native host tests**, warnings-denied core/native Clippy, Windows GNU checks, formatting and immutable source snapshots. The fresh native/frontend build passes the **142-step Linux desktop workflow**, four actual menu checks and drops at scales 1 and 2. The media-copy receipt compares source true/false callbacks, exact opaque bytes and modes, and a complete five-file BUNDLE tree with no success callback. Existing save/restore, both live projections, ZIP responsiveness, normal Quit and PID-exit checks remain intact. This milestone still needs its own complete six-job CI run; no full application performance parity is claimed.

The [first media-copy CI run](https://github.com/rob-345/freeshow-rust/actions/runs/39165878701) on `4f4b7aa4` passed Windows core and the full 142-step Linux desktop job. Linux/macOS core exposed a fixture assumption that a concurrent source overwrite could yield only either complete input string. The corrected test holds only the real `fs.copyFile` boundary until both original decisions exist, then completes both actual copies in each controlled order, asserting exact final bytes, two attempts, true reply and no source errors. It retains native first-source coalescing assertions and adds no skip. Native macOS/Windows strict checks exposed a TempDir lifetime field read only by Linux tests; its `_dir` spelling now states that retained lifetime purpose without suppressing warnings. Production copy behavior is unchanged by these corrections. A fresh complete CI run remains required.
